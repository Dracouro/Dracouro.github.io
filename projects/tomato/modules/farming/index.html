项目/火星番茄/农场系统

农场系统

从一颗种子到一株结果的番茄 —— 分阶段生长、程序化株型生成、水肥照顾与收获拾取。

进行中C++蓝图PCG

要解决的问题

种田系统最难的不是「长出来」，而是让它长得像活的：

  • 一根茎要从幼苗慢慢抽长，而不是几帧之间突然变大
  • 叶子要随机、要不对称，否则一排种下去像复制粘贴
  • 缺水、缺肥、生病要看得见，玩家不用点开面板才知道
  • 成熟了要能被收获，收获要真的产出一件能被抓、能被放进背包的东西

数据结构

作物的定义放在 DT_Farmables 里，一张表一行一种可种植物。 行结构是 C++ 的 /Script/U_Tomato.PlantData —— 不是蓝图结构体。 （这一点踩过坑：早期表结构漂移成蓝图结构体后，C++ 侧 FindRow<FPlantData> 会把内存重解释成垃圾，浇水判定恒为拒绝、水分永远 0%。现在迁移函数 MigrateFarmablesToCppStructTable 负责把旧表搬过来，旧表留在 DT_Farmables_OLD_BP。）

USTRUCT(BlueprintType)
struct FPlantData : public FTableRowBase
{
    GENERATED_BODY()

    // -- Basic --
    FText DisplayName;
    FText Description;
    TObjectPtr<UTexture2D> Icon;
    TSubclassOf<AFarmableActorBase> PlantClass;

    // -- Growth --
    /** 有序的阶段列表，植株按顺序推进 */
    TArray<FGrowingStageInfo> GrowingStages;

    // -- Requirements --
    float WaterCapacity = 100.0f;
    float FertilizerCapacity = 100.0f;
    FTemperatureRange TemperatureRange;      // 含 Min / Max / IdealMin / IdealMax

    // -- Harvest --
    FHarvestInfo HarvestInfo;                // MinYieldCount / MaxYieldCount / QualityMultiplier
    FCropQualityThresholds QualityThresholds;

    // -- Sickness --
    FSicknessInfo SicknessInfo;

    // -- Visual --
    TArray<TObjectPtr<UStaticMesh>> StemMeshes;
    TArray<FSocketTransformData> SocketTransforms;
};

生长不是「一个整数阶段数」，而是一张阶段表。 每个阶段自己带名字、时长、 可替换网格、起止缩放、以及这一阶段的耗水耗肥速率：

USTRUCT(BlueprintType)
struct FGrowingStageInfo
{
    FName  StageName;
    float  StageDuration = 60.0f;            // 秒
    TArray<TObjectPtr<UStaticMesh>> AlternativeMeshes;
    float  StartScale = 0.3f;
    float  EndScale   = 1.0f;
    float  WaterConsumptionRate = 0.5f;
    float  FertilizerConsumptionRate = 0.2f;
};

数值策划给出的番茄全长是 450 秒，五段：60 / 120 / 90 / 120 / 60。 阶段表而不是硬编码，是因为「加一种作物」这件事迟早会发生， 那时候应该只是往表里加一行，而不是去改生长代码。

从蓝图搬到了 C++

这个系统原来整个写在蓝图里（AC_Farming 组件 + BP_Farming_Master 主控蓝图）。 搬到 C++ 之后分工是这样：

角色 是什么 干什么
AFarmableActorBase C++ Actor 植株本体：推进阶段、算生长倍率、耗水耗肥、生病与掉血、收获判定
UFarmingManagerComponent C++ 组件（挂在玩家身上） 替蓝图 AC_Farming：选中作物、做射线、种植、转发浇水/施肥/治病/伤害、存档
UPlantableSurfaceComponent C++ 组件（挂在花盆上） 「这里能不能种」：容量、是否已耕、当前植株数
APlantPlacementPreviewActor C++ Actor 种植预览幽灵体
APluckableYieldActor C++ Actor 挂在植株上的果实，可摘

搬家的理由很实际：状态机、进度推进、存档序列化这三件事在蓝图里改一次要连线半小时， 在 C++ 里改一次就是改几行。 表现层（材质、粒子、动画）留在蓝图，改起来不用等编译。

种植与照顾

种植走一套「预览 → 确认」的流程，而不是点一下就冒出来：

手持种子 → BeginManualPlacement()
             └ 每帧 UpdatePlacementPreview()：幽灵体跟随射线落点
             └ IsCurrentSurfaceValidForPlanting()：查 PlantableSurfaceComponent
                  → 没超标 / 已耕 / 朝向合理 才显示为可放置
左键      → ConfirmPlacement() → SpawnSeed(Transform, RowHandle)
右键/ESC  → CancelPlacement() → 销毁幽灵体

照顾则是把玩家的「当前装备」翻译成一次调用。组件内部按 EFarmingEquipment 决定这次交互是浇水、施肥还是治病，蓝图这边只需要喊一声「对射线打到的东西用一下」：

bool TryAddWaterToFarmable(AActor* Target, float Amount);
bool TryAddFertilizerToFarmable(AActor* Target, float Amount);
bool TryCureFarmablePlant(AActor* Target);

/** 做一次相机射线，按 CurrentEquipment 路由到上面三个之一 */
void InteractWithTraceTarget();

株型是算出来的，不是摆出来的

这是这个模块里最花时间、也最像「技术美术」的部分。

植株不是一个整体模型做缩放，而是由一段段茎节程序化拼出来： 茎按抛物线分布的节长抽长、叶子按叶序角插在节点上、果穗在顶端按之字形挂果。 参数全在一个结构体里：

USTRUCT(BlueprintType)
struct FPCGPlantParams
{
    // -- 茎 --
    int32 MaxStemSegments = 18;
    float SegmentLengthMin = 6.0f;       // 根部与顶端最短
    float SegmentLengthMax = 8.0f;       // 中段最长（抛物线分布）
    float StemCurvatureAmplitude = 4.0f; // 逐节旋转幅度，茎的波状
    float StemThicknessStart = 1.5f;     // 根部半径（cm）
    float StemThicknessEnd   = 0.6f;     // 顶端半径

    // -- 叶 --
    float LeafSpiralAngle = 137.5f;      // 叶序角（黄金角）
    FPCGCompoundLeafParams CompoundLeafParams;   // 7 片小叶 / 55° 展角 / 18cm 叶轴

    // -- 果穗 --
    FPCGTrussParams TrussParams;         // 10~12 果 / 2.5cm 果距 / 0.8 之字振幅
};
  • 叶序角取 137.5° 不是随手写的 —— 那是黄金角，真实植物避免叶片互相遮挡的解。 用规则的角度而不是随机角度，一排番茄才会「看着是同一物种，但每株都不一样」。
  • 节点索引当伪随机种子：同一株每次生成结果一致（可重现），换一株又完全不同。
  • 实例化用 HISM（UPlantHISMComponent），一棵植株的几十片叶子合成一个组件， 而不是几十个 Actor —— 这是物理预算表里「Actor 数 ≤ 350」那条硬上限逼出来的做法。

调试期可以用 CVar 直接换网格，不用重新生成： PlantPCG.OverrideStemMesh / PlantPCG.OverrideLeafMesh / PlantPCG.OverrideFruitMesh。

病害：数据层已经完整，表现层还没做

病害在数据上是齐的 —— FSicknessInfo 四个参数：

字段 默认 含义
SicknessChance 0.01 每帧患病概率
GrowthPenalty 0.3 生病后生长倍率降到 30%
WaterConsumptionMultiplier 2.0 生病后耗水翻倍
HealthDecayPerSecond 2.0 不治就按秒掉血

但是「叶子长斑」那个材质没有做出来。 2026 年 4 月试过一版叶片疾病材质， 提交信息里写的是「似乎没有成功」；Content/ 里目前也确实没有对应的材质资产。 所以现在的病害是：数值上会生病、会掉血、会影响生长和收成， 但玩家看不出植株的“脸色” —— 这条是明确记在待办里的短板， 不是「已实现」。这也是为什么「六元素肥料」那条链要尽快接通： 病症如果连种类都分不出来，玩家的诊断就只能靠猜。

收获

果实是完整物品，不是植株上的一个装饰：

  • APluckableYieldActor 实现 BPI_Grabbable（CanBeGrabbed / GetGrabbablePrimitive / GetItemRowName），所以它能在场景里被点、被抓、被收进背包。
  • 采摘后植株上少一个果实，物理手柄上多一个果实模型 —— 两个方向都要对。
  • 丢回场景时网格要重新挂上 GameTraceChannel1 = Block，否则掉在地上的果实点不中。

产量与品质由 FHarvestInfo 与 FCropQualityThresholds 决定： 血量和成熟度各占一半算分，分档在 20 / 40 / 60 / 80 上。

存档

植株状态（阶段、进度、水分、肥料、血量、是否生病、位置、行名） 序列化成 FPlantSaveData，存档时 GatherAllPlantSaveData() 全场景扫一遍， 读档时 SpawnPlantsFromSave() 按数据把植株重新生成出来。 这一层走的是 C++ 侧的统一存档（见存档系统）， 不依赖蓝图序列化。

源码

PlantableSurfaceComponent.h

                // Fill out your copyright notice in the Description page of Project Settings.

#pragma once

#include "CoreMinimal.h"
#include "Components/SphereComponent.h"
#include "PlantableSurfaceComponent.generated.h"

/**
 * Component that marks an actor as a plantable surface (pot, tilled soil, garden bed, etc.).
 * Attach to any actor that should accept seeds for planting.
 *
 * The FarmingManagerComponent checks for this component on trace-hit actors
 * before allowing seed placement. This replaces the AFS Check_Tilled_Soil concept.
 */
UCLASS(ClassGroup = (Farming), meta = (BlueprintSpawnableComponent))
class U_TOMATO_API UPlantableSurfaceComponent : public USphereComponent
{
    GENERATED_BODY()

public:
    UPlantableSurfaceComponent();

    // ------------------------------------------------------------------------
    // Configuration
    // ------------------------------------------------------------------------

    /** Whether this surface must be tilled before planting. Not yet implemented
     *  (reserved for future soil-tilling mechanic). */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Plantable|Tilling")
    bool bRequiresTilling = false;

    /** Whether this surface has been tilled (only relevant if bRequiresTilling is true). */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Plantable|Tilling")
    bool bIsTilled = false;

    /** Maximum number of plants allowed on this surface. 0 means unlimited. */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Plantable|Limits", meta = (ClampMin = "0"))
    int32 MaxPlants = 1;

    /** Vertical offset override for seed spawn location (cm above surface center).
     *  0 means use the FarmingManagerComponent's default SpawnVerticalOffset. */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Plantable|Placement")
    float SpawnOffsetOverride = 0.0f;

    // ------------------------------------------------------------------------
    // Runtime State
    // ------------------------------------------------------------------------

    /** Number of plants currently growing on this surface.
     *  Incremented by FarmingManagerComponent on spawn, decremented on plant destroy. */
    UPROPERTY(BlueprintReadOnly, Category = "Plantable|Runtime")
    int32 CurrentPlantCount = 0;

    // ------------------------------------------------------------------------
    // Queries
    // ------------------------------------------------------------------------

    /** Can a new seed be planted on this surface right now?
     *  Checks tilling requirement and plant capacity.
     *  @return true if there is room and the surface is ready. */
    UFUNCTION(BlueprintPure, Category = "Plantable")
    bool CanPlant() const;

    /** Register a new plant on this surface (called by FarmingManagerComponent after spawn). */
    UFUNCTION(BlueprintCallable, Category = "Plantable")
    void RegisterPlant();

    /** Unregister a plant (called by FarmingManagerComponent when a plant is destroyed). */
    UFUNCTION(BlueprintCallable, Category = "Plantable")
    void UnregisterPlant();
};
