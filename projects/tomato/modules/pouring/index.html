倒液与容器

液体在容器与器具之间的双向转移 —— 倒出去、也抽回来，以及一条没有任何报错的静默失效。

进行中C++蓝图

要解决什么

浇水、加料、把蒸馏出来的产物从收集瓶里取走 —— 这些动作看起来都是「倒」， 但方向不同：一种是容器 → 目标，一种是器具 → 容器。 一开始只实现了前者，结果玩家能灌水却不能收集，链路两头断在半空。

所以现在的入口是一个双向的「转移」，而不是一个「倒」：

按住左键 → TransferPerSecond(Container, Target, dt)
              ├ 液体可以往目标去  → 倒（Pour）
              ├ 目标的东西可以往容器来 → 抽（Collect）
              └ 两边都不成立     → 显示「无法转移」+ 具体原因
松手     → 停止，进度条隐藏

容器到底存了什么

这是这个模块最核心的一次数据结构订正。

原来的模型里，容器装的是什么都由行类型推导出来的： DT_Items 里是液体容器就当作装水，固体容器就当作装肥料 —— 也就是说工程里根本不存在「空容器」这个状态。 CurrentCapacity = 0 的语义是「装了 0 单位水的水容器」，不是「空瓶」， 因此没有任何入口能告诉容器「你现在装的是蒸馏水」。

现在的模型把**「相」和「种类」拆开**：

概念 存在哪 含义
相（液体 / 固体） DT_Items.ToolType 容器的能力，保留不动
种类（具体是什么） ContainerFillComponent.ChemicalContent 容器的实例状态，新增 
UCLASS(ClassGroup = (Interaction), meta = (BlueprintSpawnableComponent))
class UContainerFillComponent : public UActorComponent
{
    /** 当前存量。-1 = 未初始化（沿用行/背包条目的默认值） */
    float CurrentCapacity = -1.0f;

    /**
     * 逐实例的内容物覆盖。玩家从器具收集物质时写入。
     * None = 没被覆盖：内容物按 DT_Items 行推导（液体容器表现为普通水）。
     */
    EChemicalSubstance ChemicalContent = EChemicalSubstance::None;

    bool IsInitialized() const     { return CurrentCapacity >= 0.0f; }
    bool HasChemicalContent() const { return ChemicalContent != EChemicalSubstance::None; }

    void SetCapacity(float Value)
    {
        // 把浮点残渣（< 0.01，远低于每 tick 0.5 的倒液步长）吸附到 0，
        // 让"空"成为一个稳定状态（视觉、存档、显示三处一致）
        if (Value < 0.01f) { Value = 0.0f; }
        CurrentCapacity = FMath::Max(0.0f, Value);
    }
};

三个细节值得说明：

  • -1 是「未初始化」而不是「空」。老存档、非容器物品读出来都是 -1， 加载器就保留表里的默认值 —— 于是向前兼容是自动的，不需要写迁移代码。
  • < 0.01 吸附到 0。倒液是按每 tick 的步长扣的，不收尾就会永远剩 0.003 个单位， UI 上显示为「不空」，玩家反复按也倒不干净。
  • 内容物会跟着物品走：收集到的物质镜像进背包条目的 F_ItemInfo.ContentSubstance，再进存档的 FInventorySlotSaveData.ChemicalContent —— 于是「这瓶是蒸馏水」这件事在拾取、丢弃、存档、读档四条路径上都不丢。

一个没有任何报错的坑

这是这个模块最值得记的一条 bug：

长按左键不倒液、进度条毫无变化、而且什么错都不报。

根因是 GetWorldDeltaSeconds 的 WorldContextObject 引脚没有接 Self。 UE 里带 meta=(WorldContext=...) 的函数，这个引脚不会自动填 self， 空着就返回 0 → PourPerSecond 收到的 dt <= 0 → 每帧传出 0 → 整条链静默失效。它不崩、不警告、不看代码根本查不出来。

同类问题在项目里出现过两次，所以约定也定了下来： 凡是带 WorldContext 的函数，接线时必须显式加一个 Self 节点。

顺带一条操作约定：这条链每次改完，都要复查 UI 的三处接线 （开始/持续 → 显示、进行中 → 更新、结束/取消 → 隐藏）， 而且重接脚本必须幂等（重连后补 Self），否则下次再跑会把已接好的线拆掉。

进度条

WBP_PourProgress 是一个通用提示条，四种状态：

状态 显示
倒入 目标名 + 进度 + 「按住左键倒入 · 松手停止」
抽取 目标名 + 进度 + 「按住左键抽取 · 松手停止」
被阻止 「无法转移」+ 具体原因（条置灰）
空闲 隐藏

「被阻止」这个状态是后加的，而且很关键：原来两边都不成立时直接隐藏 UI， 玩家的感受是「按了没反应」。现在它会把原因（PourUIBlockReasonText）写出来， 比如目标已经被别的东西占着了。被阻止状态的超时从 0.25 秒放宽到 1.5 秒， 是为了让人读得完那条原因。

控件是按名字契约取用的（WidgetName_Target / WidgetName_Container / WidgetName_Hint）， 改 UI 结构时不改名字就不会断链。整个控件树挂在 HitTestInvisible 下 —— 否则它会把玩家的左键吃掉。

超时兜底：UPouringProgressSubsystem 是个 UTickableWorldSubsystem， 0.25 秒没收到更新就自动隐藏。这是为了防止「松手事件丢了一次， 进度条永远挂在屏幕上」这种脏状态。

现役的「水壶」

倒液的容器就是 DT_Items 的 DistilledWater 行（BP_Item_DistilledWater， MaxCapacity = 99）—— 不要再另造一个水壶蓝图。 中途造过一次 BP_WateringCan，从关卡实例、蓝图资产到数据表行全部清理掉了。 这个物品同时也证明了另一件事：TryGrab 是从 DT_Items 行取 ItemClass 的， 所以非可装备类物品同样能上手，前提是它实现了 BPI_Grabbable。

目前的进展

C++ 主逻辑、逐实例容量与内容物、存档持久化（含五条同步路径）、 双向进度条 UI 都已落地，五个 issue 状态都是 「已实现，待人工 PIE 端到端验证」（种植侧 + 化学器具侧两条路径）。

  • 双向转移统一入口 TransferPerSecond
  • 容器逐实例容量（-1 未初始化哨兵）
  • 内容物种类（相 / 种类拆分）+ 背包与存档镜像
  • 器具 → 容器的反向装填与可行性判定
  • 进度条子系统与四态 UI（含被阻止原因）
  • 静默失效修复（WorldContext 接 Self）
  • 人工 PIE 端到端（水链路 + 肥料链路）
  • 肥料链路需要真实的肥料物品与对应 DT_Items 行
  • 倒液速率 30/s 目前是硬编码，未对齐策划数值
  • 调试屏幕打印（61701/61702）待降为开关

源码

ContainerFillComponent.h

                // Fill out your copyright notice in the Description page of Project Settings.

#pragma once

#include "CoreMinimal.h"
#include "Components/ActorComponent.h"
#include "Chemistry/ChemicalTypes.h"
#include "ContainerFillComponent.generated.h"

/**
 * Per-instance fill state for container items (liquid/solid containers).
 *
 * CurrentCapacity == -1 means "uninitialized": the container still holds the
 * default fill from its DT_Items row / inventory entry. The pouring helpers
 * create this component on demand on container actors, so container item
 * blueprints don't have to add it manually (but may, if they want the value
 * visible in the Details panel).
 */
UCLASS(ClassGroup = (Interaction), meta = (BlueprintSpawnableComponent))
class U_TOMATO_API UContainerFillComponent : public UActorComponent
{
	GENERATED_BODY()

public:
	UContainerFillComponent();

	/** Current fill amount. -1 = uninitialized (use the row/entry default). */
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Container", meta = (ClampMin = "-1"))
	float CurrentCapacity = -1.0f;

	/**
	 * Per-instance chemical content override. Set when the player collects a
	 * substance from chemistry apparatus into this container. None = not
	 * overridden: the effective content derives from the DT_Items row
	 * (a liquid container behaves as plain Water). Mirrored into the inventory
	 * entry's F_ItemInfo.ContentSubstance (when that member exists) so the
	 * substance survives pickup/drop/save-load.
	 */
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Container")
	EChemicalSubstance ChemicalContent = EChemicalSubstance::None;

	UFUNCTION(BlueprintPure, Category = "Container")
	bool IsInitialized() const { return CurrentCapacity >= 0.0f; }

	UFUNCTION(BlueprintPure, Category = "Container")
	bool HasChemicalContent() const { return ChemicalContent != EChemicalSubstance::None; }

	/** Current fill, falling back to the supplied default while uninitialized. */
	UFUNCTION(BlueprintPure, Category = "Container")
	float GetCapacityOr(float DefaultValue) const { return IsInitialized() ? CurrentCapacity : DefaultValue; }

	UFUNCTION(BlueprintCallable, Category = "Container")
	void SetCapacity(float Value)
	{
		// Snap float residue (< 0.01 units, way below the ~0.5/tick pour step) to
		// exactly 0 so "empty" is a stable state (visual + save + display).
		if (Value < 0.01f)
		{
			Value = 0.0f;
		}
		CurrentCapacity = FMath::Max(0.0f, Value);
	}

	/** Return to "uninitialized" (falls back to row/entry defaults again). */
	UFUNCTION(BlueprintCallable, Category = "Container")
	void ResetCapacity() { CurrentCapacity = -1.0f; }
};
