拼装合成系统

散件怎么粘成装配体、装配体怎么固化成成品 —— 两层合成，加上一套物理约束的调参史。

进行中C++蓝图数据表

设计取向：先推翻「重组」

最初的方案是「重组」—— 零件丢进机器里碾碎，按元素比例重新生成新物品。 做了一版之后推翻了，理由很直接：重组把玩家捡到的东西变成了数字。 一个阀门和一块铁皮在重组系统里没有区别，那玩家为什么要去找阀门？

于是改成直接从垃圾里拆零件：

你捡到一个坏掉的压缩机，拆开它，得到一个阀门、一段铜管、两颗螺栓。 这三样东西能拼成一台手动水泵。

零件有身份，玩家的每一次拆解都是在做选择。这条决定后来穿透到整个设计： 化学器材不是「玻璃片 → 研磨 → 玻璃粉 → 拉制 → 玻璃管」重新造出来， 而是从报废的蒸馏装置残骸上直接拆下玻璃管。同一件垃圾， 既能拆出管件去拼化学台，也能整个烧掉换电 —— 拆解即取舍。

两层，一个系统

这套东西实际上有两条完全不同的合成路径，工程量占了这个项目的一大半：

层 输入 → 输出 判定依据 落点
A 物理拼装层 散件 → 装配体（还在世界里，能抓能拆） 玩家摆出来的物理接触关系 BP_Glue 约束 + AC_AssemblySystem.ConstraintRecorder
B 配方固化层 装配体 → 成品 + 入库 多重集完全匹配 DT_AssemblyRecipes UAssemblyBlueprintLibrary

交接点是同一条 ConstraintRecorder：A 层往里写「哪些零件被哪些胶连起来了」， B 层按这份记录去查表。所以固化不是「再判断一次玩家拼对了没有」—— 它读的是已经发生的事实。

A 层：物理拼装

资产 角色
AC_AssemblySystem 拼装模式的宿主组件：模式开关、距离控制、ConstraintRecorder 字典、CacheActorGroup 缓存
BP_Glue 一根胶 = 一个 Actor + 一个 PhysicsConstraint，负责把两个零件鎖在一起
BP_DisableCollisionGlue 只干一件事的胶：在两件之间维持「不互相碰撞」，防止吸附后的穿模
BP_RecordConstraint 一条装配记录（MeshGroup / Actors / GlueGroup / DisableCollisionGroup）
BP_Separation 拆解时算「该恢复成几个独立物件」
AC_InteractionManager 左键分派：有记录走物理抓取，没记录走背包拾取
碰撞预设 AssemblyItem 让「拼装吸附」和「悬停拾取」两条线都打得到同一个物体

装配记录用 ComponentTags[0] 当索引键：新记录创建后必须立刻把 key 盖到组件标签上， 否则下一次查表恒为 false。这条契约踩过一次大坑 —— 第二遍查不到就会再建一条空记录， 循环永不收敛（实测 333,000 条记录后被引擎的疯狂循环护栏打断，整个 PIE 会话一起陪葬）。 契约固化成了 C++ 的 RegisterRecordComponent，创建与盖章在同一步完成。

胶的刚性：一次完整的推演

这是这个模块最花时间的一处，值得从头讲：

  • 现象：拼好的装配体拎起来，零件会绕胶点转开、甚至穿到隔壁零件里去。
  • 先量：把两条路径的约束逐字段打出来 —— 实时粘合的胶和读档恢复的胶完全相同： LinearLimit X/Y/Z = LOCKED、Cone/Twist = FREE、bDisableCollision = 1。 也就是说这不是「读档回归」，实时拼出来的同样会穿。
  • 因果链清楚了：平移锁死（所以搁得住）+ 角向全自由 + 两体碰撞被关 ⇒ 转起来没有任何东西拦得住 ⇒ 穿模。
  • 试 A 方案：把 bDisableCollision 清掉，让接触力把零件推回去。 结果只治穿模、不治偏移 —— 因为自由度的存在才是根因，松开碰撞只是让两件互推。
  • 查元凶：BP_Glue 的节点链上，设置角摇摆1限制 / 设置角摇摆2限制 / 设置角扭转限制 三个节点的默认值都是 ACM_Free，而且它们在「绑定零件 A/B」之后无条件执行， 把刚设好的角向又覆盖回自由。它们在骨骼网格分支之后，静态网格零件根本走不到， 所以真正生效的永远是这几个 CDO 默认值。
  • 落 B 方案：锁死角向（Cone/Twist 全 LOCKED），代价是失去「绕胶点自转」的手感， 换绝对不穿模、不偏移。C++ 侧提供 FinalizeGlueConstraint(Glue)， 在 A/B 解析完成后、约束建立前无条件执行，不分网格类型。

教训写进了约定：「位置没变」不能当作约束有效的证据。 PIE 会话里世界不推进，add_impulse(200000) 之后 6 秒位移仍是 0.00， 施加冲量做对照实验在这种环境里根本无效 —— 物理手感类问题只能交实机确认， 脚本能验的只有状态量（约束枚举值、A/B 身份、bDisableCollision）。

B 层：配方固化

配方表 DT_AssemblyRecipes 一行一条，行结构是 C++ 的：

/** 一条胶边：只由「零件类 + 插槽」表达，这样才能跟配方逐字段比对 */
USTRUCT(BlueprintType)
struct FAssemblyGlueEdge
{
    TSubclassOf<AActor> PartA;
    TSubclassOf<AActor> PartB;
    FName SocketA = NAME_None;
    FName SocketB = NAME_None;
};

/** 一行配方：零件多重集 + 胶边多重集 → 产物行 */
USTRUCT(BlueprintType)
struct FAssemblyRecipe : public FTableRowBase
{
    FText RecipeName;
    TArray<TSubclassOf<AActor>> RequiredParts;
    TArray<FAssemblyGlueEdge>  GlueEdges;
    /** 结果物品的 DT_Items 行名（类与网格的唯一事实源） */
    FName ResultItemRowName = NAME_None;
};

匹配是严格的多重集相等：零件集合与配方完全一致（按类比较、顺序无关）， 胶边也完全一致（按类比较、允许 A/B 互换、插槽必须一致、顺序无关）。 刻意写得很笨 —— 零件种类只有十几种，玩家一次最多摆五六个， 排序之后逐项比对是确定性的：同样的组合永远得到同样的判定， 不会因为玩家摆放顺序不同而时灵时不灵。

固化在按下固化键时才跑，没有每帧开销：

/**
 * 对 ConstraintRecorder 里第一个命中配方的装配体执行固化：
 * 销毁全部零件与胶（N 个网格 + N−1 个约束塌缩成 1 个），
 * 按配方的 DT_Items 行生成一件成品，并放进玩家背包。
 */
static bool TrySynthesizeAssembly(UObject* WorldContextObject, UActorComponent* AssemblySystem);

两个被踩出来的补丁

① 唯一的 key 不能用随机数找。

蓝图的 CreateKey 原本是「在 [1000000, 9999999] 里随机取一个 → 表里已经有就递归重取」。 它没有重试上限：随机撞号的概率再低，撞一次就是一次递归， 而递归是不会被「重试一次」救回来的。替代实现改成单调计数器分配 —— 不需要查表、不需要碰撞检测、不需要递归，因此结构上不可能死循环：

static FName MakeUniqueAssemblyKey();   // 计数器分配，唯一性是构造出来的，不是猜出来的

② 固化产物必须补登记。

固化生成的新 Actor 从来没进过 ConstraintRecorder， 于是左键点它时 GetRecordConstraint(Component).Find? 为 false → 走了「拾取进背包」的分支 → 物体从场景里消失，再也放不回地上。 RegisterSynthesizedResult 负责把新产物按「合并体」的待遇登记好 （写 map 条目 + 盖 ComponentTags[0]），这样它就能像任何装配体一样被拎起来、放下、再拆开。 散件（种子、肥料）本来就没记录，所以它们「收进背包」的路径完全不受影响。

拆解：为什么不能立刻销毁胶

BP_DisableCollisionGlue 的全部职责就是让两件零件互不碰撞。 而吸附过的零件是嵌在一起的 —— 拆解时如果当场把胶销毁， 两件在仍然重叠的状态下重新变成实心，Chaos 会以最大分离速度把它们推开： 「另一个零件嗖地飞出去」。零件质量只有 1.0，飞起来极其明显。

所以拆解改成两段式：ScheduleDisableGlueRelease 把胶交给一个延迟释放器， 等两件实际分开超过 20cm 之后再销毁胶（3 秒超时兜底，防止玩家永远不分开而泄漏）。 在不再穿透的状态下恢复碰撞，世界就安静了。

存档：两套存档系统并存

这是全项目最绕的一块，值得单独记住：

系统 文件 数据 谁在写
面板存档 Saved/SaveGames/BlueprintSave.sav BP_BlueprintGameSave.SavingData（TMap<FName, F_SavingData>） 存档面板 / 「N」键
C++ 统一存档 Saved/SaveGames/Slot0.sav UTomatoSaveSubsystem 里的装配体 blob 自动存档定时器

两个真实故障，都是从这里长出来的：

  • 幽灵档复活：AC_AssemblySystem.GameSaveData 只在 BeginPlay 从磁盘加载一次， 从此永不刷新。面板列表读的是这个旧缓存，删除操作也作用在它上面 —— 于是「删掉的档过一会儿自己回来了」。修法是两条： 面板打开前先 RefreshAssemblySaveData（把组件对齐到磁盘）， 删除后立刻 PersistAssemblySaveData（删完要落盘）。另外让 GatherAssemblyFromComponent 在收集前先重载面板存档， 使面板存档成为存档名的权威来源，自动存档不再把旧名字塞回去。
  • 空档覆盖满档：给「删除」流程加「保险式落盘」曾经是个回归 —— 它读不到 map（日志 -1 entries）却照样写盘，把刚删好的档覆盖成 1944 字节的空档。 教训：不要给已经正确的链路加保险，加之前先把原链路的每一个引脚读完。

还有个更隐蔽的坑：装配体数据走的是 FObjectAndNameAsStringProxyArchive 逐结构体序列化， 而它使用的蓝图结构体成员没有 CPF_SaveGame 标记。 一旦给归档设上 ArIsSaveGame，引擎会跳过所有没这个标记的字段 —— 写出来的 blob 恒为 9 字节空壳。判据就此固定下来： blob 长度 9 = 空，上百字节 = 有数据。

一处典型的「悬空引用」

AC_InteractionManager 用 LookAtActor 缓存「当前看向的对象」。 拾取种子时 TryGrab 把种子收进背包后立刻 DestroyActor， 但 LookAtActor 没有清空 —— 下一次点击对接口做动态转换时， 访问的已经是一个正在等待回收的对象：

已尝试通过属性 K2Node_DynamicCast_AsBPI_Grabbable 访问 BP_SEEDTEX_C_1， 但该对象无效（等待销毁或垃圾回收）。

两处一起修：根治是抓取成功后立刻清空 LookAtActor； 兜底是在 CanBeGrabbed 之前补一道 IsValid 守卫。 关键在于「缓存指向世界对象的引用」这件事本身就是个坑 —— 清引用要跟销毁动作绑在一起，而不是指望下一个使用者自己去校验。

目前的进展

物理层与配方层都已实现，16 条以上 issue 的修法全部落地，编译通过、实机确认过 「之前说的问题都修完了」，但绝大多数票据状态仍是 「已修复，待人工 PIE 手感确认」 —— 这也是这个项目里票据系统的诚实之处。

  • ConstraintRecorder 记录契约 + ComponentTags[0] 索引
  • 胶约束刚性化（角向锁死）
  • 配方表结构与多重集匹配（零件 + 胶边，A/B 可换）
  • TrySynthesizeAssembly 固化（销毁零件与胶 → 生成成品 → 入库）
  • 唯一 key 改单调计数（消除递归死循环）
  • 固化产物补登记（修复「点一下就进背包」）
  • 拆解的两段式胶释放（消除「另一件被弹飞」）
  • 拼装存档：命名、缩略图、删除持久化、幽灵档清除
  • 左键悬空引用（LookAtActor）修复
  • 正式配方（当前只有测试配方 Recipe_2xCube，正式配方依赖美术预置的合并网格）
  • 右键拆解链的执行线
  • 零件之间的物理导向/预览
  • 多步合成（中间体参与后续配方）
  • 一批物理手感问题仍需实机确认（穿模、抖动、抓取距离）

AssemblyTypes.h

                // Fill out your copyright notice in the Description page of Project Settings.

#pragma once

#include "CoreMinimal.h"
#include "Engine/DataTable.h"
#include "GameFramework/Actor.h"
#include "AssemblyTypes.generated.h"

/**
 * A single glue joint between two assembled parts, expressed purely as part
 * classes + sockets so it can be compared against a recipe definition.
 * Mirrors the connection fields of the Blueprint F_GlueInfo (AActorClass /
 * BActorClass / SocketA / SocketB).
 */
USTRUCT(BlueprintType)
struct FAssemblyGlueEdge
{
	GENERATED_BODY()

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Edge")
	TSubclassOf<AActor> PartA = nullptr;

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Edge")
	TSubclassOf<AActor> PartB = nullptr;

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Edge")
	FName SocketA = NAME_None;

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Edge")
	FName SocketB = NAME_None;
};

/**
 * One row of DT_AssemblyRecipes: the multiset of required parts + glue edges
 * that a finished assembly must match, plus the DT_Items row that provides the
 * result's class and static mesh (single source of truth for the result).
 */
USTRUCT(BlueprintType)
struct FAssemblyRecipe : public FTableRowBase
{
	GENERATED_BODY()

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
	FText RecipeName;

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
	TArray<TSubclassOf<AActor>> RequiredParts;

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
	TArray<FAssemblyGlueEdge> GlueEdges;

	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
	FName ResultItemRowName = NAME_None;
};

/**
 * The parts a restored glue joint connects, as recorded in the save.
 *
 * Mirrors the fields of the Blueprint F_GlueInfo that ResolveGlueParts needs. The
 * Blueprint struct cannot be referenced from C++ (it is a UserDefinedStruct whose
 * fields carry GUID suffixes), so the Blueprint side copies those fields into this
 * native struct at the call site.
 */
USTRUCT(BlueprintType)
struct FAssemblyGlueRecord
{
	GENERATED_BODY()

	/** Class of the first part actor. */
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Glue")
	TSubclassOf<AActor> AActorClass = nullptr;

	/** Class of the second part actor. */
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Glue")
	TSubclassOf<AActor> BActorClass = nullptr;

	/** Part A's transform relative to the glue's recorded location. */
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Glue")
	FTransform AActorTrans = FTransform::Identity;

	/** Part B's transform relative to the glue's recorded location. */
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Glue")
	FTransform BActorTrans = FTransform::Identity;
};
