存档系统

植株、背包、快捷栏、装配体怎么活过重启 —— 以及一个「删掉的存档自己回来」的完整解剖。

进行中C++蓝图

一个总线式的存档

存档做成了 GameInstanceSubsystem，任何系统都能直接拿到它，不需要互相持有引用：

GetGameInstance()->GetSubsystem<UTomatoSaveSubsystem>()

保存与载入都是**「C++ 先存自己那份，再广播让蓝图补上」**的两段式：

SaveGame(SlotName)
  1. 建一个 UTomatoSaveGame
  2. C++ 侧收集：植株状态、快捷栏、背包容器容量
  3. 广播 OnSaveGather ── 蓝图系统（背包、装配体）往同一个对象里塞数据
  4. SaveGameToSlot 落盘

LoadGame(SlotName)
  1. 从磁盘读 UTomatoSaveGame
  2. 广播 OnSaveRestore ── 蓝图系统自己恢复
  3. C++ 侧直接恢复（植株、快捷栏）

这个「广播 + 各自认领」的结构让新系统接入存档的成本变成一行绑定 —— 但它也带来一个必须正视的后果：谁往同一个槽里写、写的顺序是什么， 变成了一个全局性的约定。下面两节就是这个约定没立好时发生的事。

自动存档间隔默认 10 分钟，由 BP_Farmer 在 BeginPlay 里起定时器。 另外有个小查询 GetTimeSinceLastSaveText() 直接返回「刚刚 / 10 分钟前 / 尚未保存」， 给 UI 用。

两套存档并存（这是绕不开的现实）

项目里同时存在两个 .sav 文件，它们不是同一个东西：

系统 文件 装什么 谁在写
面板存档 Saved/SaveGames/BlueprintSave.sav BP_BlueprintGameSave.SavingData（TMap<FName, F_SavingData>，key = 存档名） 拼装存档面板、「N」键
C++ 统一存档 Saved/SaveGames/Slot0.sav UTomatoSaveSubsystem 里的装配体 blob + 植株 + 背包 + 快捷栏 自动存档定时器

装配体数据通过 SerializeLegacyAssemblyToSubsystem / DeserializeSubsystemToLegacyAssembly 在两个系统之间往返 —— 这层适配是历史包袱（装配体系统原本是一套独立的蓝图存档）， 但它也是这个模块里 bug 密度最高的地方。

「删掉的存档自己回来了」

这个 bug 追了很久，机制值得完整解剖一遍：

  1. 面板列表读的是组件缓存：AC_AssemblySystem.GameSaveData 只在 BeginPlay 从磁盘加载一次，从此永不刷新。
  2. 玩家在面板里删掉一条 → 删除作用在组件缓存上 → 磁盘没动。
  3. 下次启动照旧从磁盘加载 → 被删的档回来了。

修法是三件事，缺一不可：

位置 动作
面板 Construct RefreshAssemblySaveData() —— 组件先对齐磁盘，再填列表
删除流程 PersistAssemblySaveData() —— 删完立刻落盘
自动存档收集 GatherAssemblyFromComponent() 前先重载面板存档，让面板存档成为存档名的权威来源

第三件事是根治：SaveGame() 每次都会 NewObject 造一个新的存档对象并广播收集， 而蓝图侧的收集读的是组件缓存 —— 只要缓存里还留着旧名字， 它就会被重新写回 Slot0.sav，甚至再灌回面板。让面板存档当权威来源之后， 「自动存档把幽灵名字搬回来」这条回路才算断掉。

一个被自己制造出来的回归

修「删除不持久」的过程中，我曾给删除流程加了一个「保险式落盘」， 结果它读不到 map（日志里是 -1 entries）却照样写盘， 把刚删好的档覆盖成 1944 字节的空档。

教训已经写进项目约定：

  • 不要给已经正确的链路加保险。 加之前先把原链路的每一个引脚读完， 搞清楚它到底做了什么 —— DeletData 本来就已经做了「删一个 key + 落盘」两件事。
  • 文件大小是重要线索：1944 字节 = 空档（SavingData 属性整个消失）， 6800 左右 ≈ 只有一两条档，11000+ ≈ 三条。字节数骤降就是丢字段的信号。
  • 任何存档实验之前必须备份 .sav，改完必须重新加载验证 key 列表。

一个只会写空壳的序列化设置

装配体数据走的是 FObjectAndNameAsStringProxyArchive，逐结构体序列化 蓝图结构体 F_SavingData。而蓝图 UserDefinedStruct 的成员没有 CPF_SaveGame 标记。

于是当有人「顺手」给归档设上 ArIsSaveGame = true 时， 引擎在 FProperty::ShouldSerializeValue 里会跳过所有没有这个标记的字段 —— 蓝图结构体的成员全都没这个标记，结果写出来的 blob 恒为 9 字节空壳， 读回来是空结构：读档后零件、胶、缓存全空，零件没有组件标签，点也点不动、拼也拼不上。

判据就此固定：

blob 长度 9 = 空壳；上百字节 = 有数据。

（UTomatoSaveGame 自己的 Plants / InventorySlots / HotbarSlots 走的是 USaveGame 的 UPROPERTY 序列化，不受这个坑影响 —— 这也是为什么它只坏在装配体那一条上。）

怎么读一个 .sav

排查存档问题时，最直接的办法是字节级扫描，而不是等加载器报错：

$b = [IO.File]::ReadAllBytes('Saved\SaveGames\BlueprintSave.sav')
-join ($b | %{ if ($_ -ge 32 -and $_ -lt 127) { [char]$_ } else { '.' } })
  • 文件末尾 16 字节是 None 结束标记；类名后面紧跟 None 且没有属性流 = 空存档。
  • 用正则数关键 key 出现次数，就能判断某个档到底在不在里面。
  • 结构体字段（比如 ScreenshotPath）用 Python 反射读会失败 —— 成员名带 GUID 后缀，属正常限制，改走字节扫描。

缩略图那一段插曲

拼装存档的缩略图原本有一个名字兼两个用途：既是存档名，又是截图文件名。 于是同名重存会覆盖同名 png —— 而每条存档都指向那个 png， 改一张图，所有老存档的预览图一起变（玩家反馈是「老存档显示了别人的模型」）。

修法是拆开两件事：存档名不动（它是 map 的 key，也是列表显示的东西）， 只让文件名唯一（追加时间戳）。另外顺手修正了两处：

  • 蓝图拼出来的截图路径是错的（指向一个不存在的 Saved\Automation\... 目录， 是条死支路），真正落盘的位置是 Saved/Screenshots/<平台名>/；
  • 那个「只当数据源用的函数」被蓝图编译器当成无用代码修剪掉了 （日志原话：已被修剪，因为其执行引脚未连接）， 导致存下来的是空名字、缩略图路径畸形 —— 声明成纯函数才修好。

目前的进展

  • UTomatoSaveSubsystem 总线（保存/载入/存在性/删除/最后存档时间）
  • 植株、背包（含容器容量与内容物）、快捷栏的 C++ 侧存取
  • 蓝图系统的 OnSaveGather / OnSaveRestore 接入口
  • 自动存档（默认 10 分钟）
  • 两套存档的往返适配（装配体 blob）
  • 幽灵档清除与删除持久化
  • 存档命名唯一化、缩略图文件唯一化
  • 跨局继承（策划案的 P1：数据活过「重开一局」）
  • 存档版本与迁移（现在 Version 字段只做记录，没有迁移分支）

源码

TomatoSaveSubsystem.h

                // Fill out your copyright notice in the Description page of Project Settings.

#pragma once

#include "CoreMinimal.h"
#include "Subsystems/GameInstanceSubsystem.h"
#include "TomatoSaveGame.h"
#include "TomatoSaveSubsystem.generated.h"

DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnSaveGather, UTomatoSaveSubsystem*, Subsystem);
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnSaveRestore, UTomatoSaveSubsystem*, Subsystem);

class UFarmingManagerComponent;
class UHotbarManagerComponent;

/**
 * Unified save system orchestrator.
 * Auto-initializes as a GameInstanceSubsystem — accessible from anywhere via
 * GetGameInstance()->GetSubsystem<UTomatoSaveSubsystem>().
 *
 * Save flow:
 *   1. SaveGame() creates a UTomatoSaveGame, gathers C++ data (farming, hotbar),
 *      then fires OnSaveGather so BP systems (inventory, assembly) can contribute.
 *   2. Writes to disk via UGameplayStatics::SaveGameToSlot.
 *
 * Load flow:
 *   1. LoadGame() reads from disk, fires OnSaveRestore so BP systems can restore.
 *   2. C++ systems (farming, hotbar) are restored directly.
 */
UCLASS()
class U_TOMATO_API UTomatoSaveSubsystem : public UGameInstanceSubsystem
{
	GENERATED_BODY()

public:
	// ------------------------------------------------------------------------
	// Subsystem Lifecycle
	// ------------------------------------------------------------------------

	virtual void Initialize(FSubsystemCollectionBase& Collection) override;
	virtual void Deinitialize() override;

	// ------------------------------------------------------------------------
	// Public Save/Load API
	// ------------------------------------------------------------------------

	/** Save all game state to the given slot. Fires OnSaveGather. */
	UFUNCTION(BlueprintCallable, Category = "Save")
	bool SaveGame(const FString& SlotName);

	/** Load all game state from the given slot. Fires OnSaveRestore. */
	UFUNCTION(BlueprintCallable, Category = "Save")
	bool LoadGame(const FString& SlotName);

	/** Check whether a save exists for the given slot. */
	UFUNCTION(BlueprintPure, Category = "Save")
	bool DoesSaveExist(const FString& SlotName) const;

	/** Delete the save file for the given slot. */
	UFUNCTION(BlueprintCallable, Category = "Save")
	bool DeleteSave(const FString& SlotName);

	/** Get the loaded save game object (valid after LoadGame, or during save gather). */
	UFUNCTION(BlueprintPure, Category = "Save")
	UTomatoSaveGame* GetCurrentSave() const { return CurrentSave; }

	// ------------------------------------------------------------------------
	// Farming Data — set by C++ during save gather, read during load restore
	// ------------------------------------------------------------------------

	UFUNCTION(BlueprintCallable, Category = "Save|Farming")
	void SetPlants(const TArray<FPlantSaveData>& Data);

	UFUNCTION(BlueprintPure, Category = "Save|Farming")
	const TArray<FPlantSaveData>& GetPlants() const;

	// ------------------------------------------------------------------------
	// Inventory Data — set/get by BP during save gather / load restore
	// ------------------------------------------------------------------------

	UFUNCTION(BlueprintCallable, Category = "Save|Inventory")
	void SetInventorySlots(const TArray<FInventorySlotSaveData>& Slots);

	UFUNCTION(BlueprintPure, Category = "Save|Inventory")
	const TArray<FInventorySlotSaveData>& GetInventorySlots() const;

	/** After OnSaveGather, copy each inventory entry CurrCapacity into the matching slot. */
	void SyncInventoryCapacitiesToSlots();

	/** After OnSaveRestore, copy each slot CurrCapacity back into the matching inventory entry. */
	void RestoreInventoryCapacitiesFromSlots();

	/** Scan DT_Items for a row whose ItemID matches, and return its row FName (or NAME_None). */
	UFUNCTION(BlueprintCallable, Category = "Save|Inventory")
	FName FindItemRowNameByID(int32 ItemID) const;

	// ------------------------------------------------------------------------
	// Hotbar Data — set by C++ during save gather, read during load restore
	// ------------------------------------------------------------------------

	UFUNCTION(BlueprintCallable, Category = "Save|Hotbar")
	void SetHotbarData(const TArray<FHotbarSlotSaveData>& Slots, EFarmingEquipment Equipment);

	UFUNCTION(BlueprintPure, Category = "Save|Hotbar")
	const TArray<FHotbarSlotSaveData>& GetHotbarSlots() const;

	UFUNCTION(BlueprintPure, Category = "Save|Hotbar")
	EFarmingEquipment GetSavedEquipment() const;

	// ------------------------------------------------------------------------
	// Assembly Data — set/get by BP during save gather / load restore
	// ------------------------------------------------------------------------

	UFUNCTION(BlueprintCallable, Category = "Save|Assembly")
	void SetAssemblySaveData(const FString& SaveName, const TArray<uint8>& SerializedData);

	UFUNCTION(BlueprintPure, Category = "Save|Assembly")
	bool GetAssemblySaveData(const FString& SaveName, TArray<uint8>& OutData) const;

	UFUNCTION(BlueprintPure, Category = "Save|Assembly")
	TArray<FString> GetAllAssemblySaveNames() const;

	UFUNCTION(BlueprintCallable, Category = "Save|Assembly")
	void RemoveAssemblySaveData(const FString& SaveName);

	/** Iterate a legacy BP_BlueprintGameSave's SavingData TMap and push each serialized F_SavingData into the unified save. */
	UFUNCTION(BlueprintCallable, Category = "Save|Assembly")
	void SerializeLegacyAssemblyToSubsystem(UObject* LegacySaveObject);

	/** Read all assembly blobs from the unified save and deserialize them back into the legacy BP_BlueprintGameSave's SavingData TMap. */
	UFUNCTION(BlueprintCallable, Category = "Save|Assembly")
	void DeserializeSubsystemToLegacyAssembly(UObject* LegacySaveObject);

	/** Find GameSaveData on the component via reflection, iterate its SavingData TMap, and push serialized entries into CurrentSave. Call from HandleSaveGather. */
	UFUNCTION(BlueprintCallable, Category = "Save|Assembly")
	void GatherAssemblyFromComponent(UActorComponent* AssemblyComponent);

	/** Read assembly blobs from CurrentSave, deserialize into GameSaveData on the component (creating it if needed). Call from HandleSaveRestore. */
	UFUNCTION(BlueprintCallable, Category = "Save|Assembly")
	void RestoreAssemblyToComponent(UActorComponent* AssemblyComponent);

	// ------------------------------------------------------------------------
	// Delegates — BP systems bind to these for save/load participation
	// ------------------------------------------------------------------------

	/** Fired during SaveGame after C++ data is gathered. BP listeners push their data here. */
	UPROPERTY(BlueprintAssignable, Category = "Save|Events")
	FOnSaveGather OnSaveGather;

	/** Fired during LoadGame after disk read. BP listeners restore state from loaded data here. */
	UPROPERTY(BlueprintAssignable, Category = "Save|Events")
	FOnSaveRestore OnSaveRestore;

	// ------------------------------------------------------------------------
	// Auto-Save
	// ------------------------------------------------------------------------

	/** Auto-save interval in minutes. Default 10.0. */
	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Save|AutoSave")
	float AutoSaveIntervalMinutes = 10.0f;

	/** Start the periodic auto-save timer. Call from BP_Farmer BeginPlay. */
	UFUNCTION(BlueprintCallable, Category = "Save|AutoSave")
	void StartAutoSave();

	/** Stop the periodic auto-save timer. */
	UFUNCTION(BlueprintCallable, Category = "Save|AutoSave")
	void StopAutoSave();

	/** Whether auto-save timer is currently active. */
	UFUNCTION(BlueprintPure, Category = "Save|AutoSave")
	bool IsAutoSaveActive() const { return AutoSaveTimerHandle.IsValid(); }

	// ------------------------------------------------------------------------
	// Last Save Time Queries
	// ------------------------------------------------------------------------

	/** Get the real-world timestamp of the last save (or MinValue if never saved). */
	UFUNCTION(BlueprintPure, Category = "Save|Time")
	FDateTime GetLastSaveTimestamp() const;

	/** Human-readable text: "10分钟前" / "刚刚" / "尚未保存". */
	UFUNCTION(BlueprintPure, Category = "Save|Time")
	FText GetTimeSinceLastSaveText() const;

protected:
	/** Find the player pawn by walking local player → controller → pawn. */
	APawn* GetPlayerPawn() const;

	/** Cache pointers to C++ components on the player pawn. */
	void CachePlayerComponents();

	// ------------------------------------------------------------------------
	// In-memory save object
	// ------------------------------------------------------------------------

	UPROPERTY()
	TObjectPtr<UTomatoSaveGame> CurrentSave;

	// ------------------------------------------------------------------------
	// Cached C++ component references (resolved from player pawn)
	// ------------------------------------------------------------------------

	UPROPERTY()
	TObjectPtr<UFarmingManagerComponent> CachedFarmingManager;

	UPROPERTY()
	TObjectPtr<UHotbarManagerComponent> CachedHotbarManager;

	/** Pawn we last cached from. Reset when pawn changes. */
	UPROPERTY()
	TWeakObjectPtr<APawn> CachedPawn;

private:
	static constexpr int32 SaveUserIndex = 0;

	/** Timer handle for the periodic auto-save. */
	FTimerHandle AutoSaveTimerHandle;

	/** Internal callback fired by the auto-save timer. */
	void OnAutoSaveTimerTick();
};
