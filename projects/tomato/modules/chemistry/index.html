化肥提炼与化学合成

把垃圾拆成零件、拼成器材、再炼成六种基础元素的完整链路 —— 以及为什么玩家该在乎自己捡的是什么。

进行中C++数据表

要解决什么

农场系统的病害表现是能跑的，但玩家凭什么去治它？ 需要一条从「垃圾」到「肥料」的通路，而且这条通路要有游戏性 —— 不能是「捡三个垃圾，点一下，得到一袋化肥」。

分层

整条链分四层，每一层都能独立成立：

层 名字 举例 来源
L0 垃圾 锈蚀的罐头、废电池、塑料桶 场景里捡 / 传送带送来
L1 材料与零件 铁皮、锌壳、电解液、玻璃管、橡胶塞、软管、滤材 拆解 L0
L2 中间体 硫酸、氨液、硝酸钾粗品、木炭、玻璃粉 化学合成 / 加工站
L3 产物 氮肥、磷肥、钾肥… 精制

关键在于 L1 是零件不是元素。一块铁皮可以拿去修水泵，也可以拿去做硫酸亚铁 —— 同一件东西有两个用途，玩家得做取舍。这才是这条链存在的意义。

六种元素

元素 作用 缺素症状 主要来源
N 氮 促叶片生长 老叶均匀黄化 有机垃圾发酵 → 氨液 → 蒸馏
P 磷 促根系与开花 叶背与茎发紫 磷酸盐渣、骨粉营养砖（P+Ca）
K 钾 抗病、抗逆 叶缘焦枯 焚化木质 → 木灰；海盐苦卤残渣
Ca 钙 细胞壁强度 新叶卷曲 石膏板碎块（CaSO₄ → Ca+S）、蛋壳粉
Mg 镁 叶绿素核心 脉间失绿 泻盐块（MgSO₄ → Mg+S）、镁牺牲阳极
S 硫 蛋白质合成、杀菌 幼叶失绿 硫磺矿、硫化橡胶残片

这六种不是随便选的 —— 它们正好构成缺素症状可分辨的最小集合。 玩家看一眼植株的颜色，就能反推该补哪一种。看得懂的症状 = 不用查攻略。

设计上还有一层化学彩蛋：几件垃圾直接带真实化学式， 石膏板 = CaSO₄ 同时给 Ca 和 S，泻盐块 = MgSO₄ 同时给 Mg 和 S —— 一件垃圾两个产出，于是「直接拆解」和「烧掉换电」之间出现了真实的取舍 （硫化橡胶残片焚化值 20 EU 是全场最高，但它也是 S 的唯一稳定来源）。

工艺与器材

覆盖六类基本操作，互相之间可以串联：

工艺 做什么 需要的器材
蒸馏 按沸点分离液体混合物 烧瓶 + 冷凝器 + 收集瓶
发酵 靠微生物把有机物转成可提取态 发酵器 + 温控
过滤 固液分离、提纯 漏斗 + 滤材 + 铁架台
酸浸 把金属从矿石/合金里溶出来 耐酸容器 + 加热
水溶 把可溶盐带进溶液 烧杯 + 搅拌
混合 配复合液、暂存 烧杯

工艺之间是有依赖的：想酸浸，得先蒸馏出酸；想蒸馏，得先拼出冷凝器。 器材本身又得靠上一节（拼装合成）拼出来 —— 两个系统在这里咬合上， 这也是为什么化学这个模块一大半的工作量其实花在拼装配方上。

器材与零件的反向映射

设计上换了个方向：不是问「拼出器材需要哪些零件」，而是问 「垃圾堆里能拆出的哪些零件，恰好能拼成一件器材」。

这样做的实际好处是，地图上散落的垃圾可以被反向设计 —— 想让玩家在这个区域学会蒸馏，就保证这一片能拆出一套完整的蒸馏器材。 关卡设计因此有了抓手。

器材 需要零件 可拆自
烧瓶 玻璃罩、软木塞 废弃灯具、保温瓶
冷凝器 玻璃管 ×2、软管 ×2 报废蒸馏装置残骸、冰箱、空调外机
收集瓶 玻璃罐、橡胶垫圈 罐头、密封舱门
过滤器 金属网、滤材 废 HEPA 滤芯、纱窗、防护服
发酵器 罐体、密封盖、气阀 报废生物反应器罐体、储水桶
铁架台 单件即成品 报废实验台架、三脚架
烧杯 单件即成品 报废烧杯、破碎量杯
加热台 发热体 + 温控 + 电源线 + 外壳 + 开关 旧电炉盘、控制板、废电源线…

连炉子都得自己捡这套逻辑，是在「房间里本来什么都没有」这条硬设定下推出来的： 玩家自造范围的最后边界落在 8 件器材上，只有研磨台 / 焚化炉 / 发酵角三个加工站 是预置基础设施。

有一处编号冲突值得记一下：早期文档把铁架台写成 RE-05、烧杯写成 RE-07， 而策划案里这两个编号已经被「金属夹」和「木炭」占了 —— 直接后果是 DT_Items 行名冲突。裁定后改为 RE-19 铁架台、RE-20 烧杯，L2 层的编号范围收敛到 RE-01~22。 行名冲突这种错，在表格驱动 + 表间引用的项目里是最贵的一类，因为它不会报错， 只会静默取到另一个物品。

工程实现：化学台

化学台是一套「器具集合 + 输入多重集 → 产物」的自动匹配： 玩家不需要在 UI 里选配方，摆对了就会自己认。

/** 反应台状态机 */
enum class EChemicalStationState : uint8
{
    Idle,        // 什么都没摆
    Ready,       // 器具齐了、输入够了，等启动信号
    Processing,  // 反应中
    Produced,    // 产物已生成，等收集
};
USTRUCT(BlueprintType)
struct FChemicalRecipe : public FTableRowBase
{
    FText RecipeName;
    /** 这些器具必须全部就位（集合 ⊇ 即可，不要求顺序） */
    TArray<EChemicalApparatus> RequiredApparatus;
    /** 这些输入物质必须齐全（多重集 ⊆ 即可） */
    TArray<EChemicalSubstance> RequiredInputs;
    EChemicalSubstance OutputSubstance = EChemicalSubstance::None;
    float ProcessTime = 5.0f;
    /** true = 要炉子电源按钮按下才启动（加热类）；false = 输入齐了就自动跑（催化类） */
    bool  bRequiresHeat = false;
};

两个设计决定：

  • 热源不进器具枚举。 EChemicalApparatus 只有烧瓶 / 冷凝器 / 收集瓶三种， 没有 HeatSource —— 加热由 BP_Stove 的电源按钮提供。 这样「谁在耗电」这件事只有一个归属，不用在两个系统之间对账。
  • 启动要电。 每次反应向电力系统扣 4 EU（TrySpendPowerFor(ChemistryStation)）， 电力见电力系统。

化学的 ID 体系（EChemicalSubstance 等 uint8 枚举）刻意与物品系统解耦， 两者之间只有一个接缝：FChemicalSubstanceDef.InventoryItemRowName —— 物质要变成一件能收进背包的东西时，才去查 DT_Items 的行名。 这一条隔离做得很值：化学系统改物质表，物品系统一行都不用动。

⚠️ 已经实现的比设计少得多

必须说清楚当前的真实边界，否则会误以为六元素链已经在跑：

层 状态
反应台框架（状态机 / 器具匹配 / 输入多重集 / 加热门控 / 扣电 / 收集） ✅ 已实现
容器与器具的液体交互（倒液、收集） ✅ 已实现（水链路）
EChemicalSubstance 里实际存在的物质 ⚠️ 只有 None / Water / DistilledWater 三条
FChemicalComposition（N/P/K/Ca/Mg/S 六元素成分） ⚠️ 结构体已定义，与植株生长之间没有数据通路
上半章的 L0→L3 分层、六元素、8 件器材、RE-01~22 零件表 📐 设计层（在 docs/ 里，尚未全部落表落资产）

所以现在能演示的最长链路是：给烧瓶灌水 → 器具就位 → 炉子通电扣 4 EU → 反应中 → 收集瓶被染上颜色 → 收集入库 → 手持蒸馏水去浇花盆。

而且这条链的首尾数值还不通：蒸馏水和白水对植株的效果完全一样， 因为 TryAddWater(float) 收不到「这是蒸馏水」这个信息 —— 这就是上面那条「六元素没有数据通路」的具体表现。

数据表的一致性靠脚本守

垃圾与生成物这一层文档量很大（垃圾总表、扩展生成物总表、生成物美术资产表、 AI 批量出图提示词），为了避免它们互相漂移，约定是：

  • 唯一事实源：扩展生成物总表 里的 120 个 Junk_* 行名 = 数值 + 外观的唯一来源。
  • 往总表加物品后必须跑 python Tools/check_art_coverage.py （退出码 0 = 通过，校验行名覆盖与各族件数）。
  • 改完美术表必须重跑 python Tools/gen_art_batch_prompts.py 重生成提示词全集（生成物头部写着「请勿手工编辑」）。

这套检查脚本抓到过一次真问题：美术资产表只覆盖了 114/120，漏了 6 件， 其中 Junk_PotashBlock（钾肥盐块）是钾的两条直给来源之一 —— 漏掉它，钾链就只剩一条路。机器能查的东西不该留给眼睛。

待确认

  • 六种元素是否够用 —— 是否需要一个「复合肥」的中间态
  • 酸浸的腐蚀风险要不要做成机制（穿防护服 / 弄坏器材）
  • 器材是否需要耐久与损耗
  • 六元素成分 → 养分池 → 生长的接线（当前最大的断点）
  • 化学器具清单是否完整（设计与策划案已经对过一轮编号，再确认一次）

源码

ChemicalTypes.h

                // Fill out your copyright notice in the Description page of Project Settings.

#pragma once

#include "CoreMinimal.h"
#include "Engine/DataTable.h"
#include "Internationalization/Text.h"
#include "Materials/MaterialInterface.h"
#include "Math/Color.h"
#include "ChemicalTypes.generated.h"

// ------------------------------------------------------------------------
// Chemistry refining station — shared identity & data types.
// Independent, low-overhead ID system (uint8 enums) decoupled from the
// existing inventory ItemID / DT_Items.ItemName scheme.
// ------------------------------------------------------------------------

/** Discrete refinable substances. Extend with fertilizer compounds as needed. */
UENUM(BlueprintType)
enum class EChemicalSubstance : uint8
{
    None            UMETA(DisplayName = "None"),
    Water           UMETA(DisplayName = "Water"),
    DistilledWater  UMETA(DisplayName = "Distilled Water"),
};

/**
 * Apparatus (glassware) types the station can recognize.
 * Heat is supplied by the BP_Stove power button, not by a glueable apparatus,
 * so there is intentionally no HeatSource member here.
 */
UENUM(BlueprintType)
enum class EChemicalApparatus : uint8
{
    None            UMETA(DisplayName = "None"),
    Flask           UMETA(DisplayName = "Flask"),
    Condenser       UMETA(DisplayName = "Condenser"),
    CollectionVessel UMETA(DisplayName = "Collection Vessel"),
};

/** Physical state of a substance (drives future simulation, visuals). */
UENUM(BlueprintType)
enum class EChemicalState : uint8
{
    Solid   UMETA(DisplayName = "Solid"),
    Liquid  UMETA(DisplayName = "Liquid"),
    Gas     UMETA(DisplayName = "Gas"),
};

/**
 * Reaction state machine for the station.
 * Ready = apparatus assembly + inputs are complete, awaiting the start signal
 * (heat recipes wait for the stove power button; auto recipes skip straight
 * to Processing).
 */
UENUM(BlueprintType)
enum class EChemicalStationState : uint8
{
    Idle        UMETA(DisplayName = "Idle"),
    Ready       UMETA(DisplayName = "Ready"),
    Processing  UMETA(DisplayName = "Processing"),
    Produced    UMETA(DisplayName = "Produced"),
};

/**
 * Six-element fertilizer composition (N/P/K/Ca/Mg/S) as continuous quantities.
 * Matches the legacy Blueprint F_Requirements / BP_Farming_Master element model.
 * Water / distilled water have all-zero composition; future fertilizer
 * substances fill these to drive plant growth.
 */
USTRUCT(BlueprintType)
struct FChemicalComposition
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Composition")
    float Nitrogen = 0.0f;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Composition")
    float Phosphorus = 0.0f;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Composition")
    float Potassium = 0.0f;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Composition")
    float Calcium = 0.0f;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Composition")
    float Magnesium = 0.0f;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Composition")
    float Sulfur = 0.0f;
};

/** Data-table row: defines how a substance looks (material + color) and its content. */
USTRUCT(BlueprintType)
struct FChemicalSubstanceDef : public FTableRowBase
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Substance")
    EChemicalSubstance SubstanceID = EChemicalSubstance::None;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Substance")
    FText DisplayName;

    /** Liquid/disc material assigned to the substance display mesh on production. */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Substance")
    TObjectPtr<UMaterialInterface> Material = nullptr;

    /** Tint applied to the substance material's "Color" vector parameter. */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Substance")
    FLinearColor Color = FLinearColor::White;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Substance")
    EChemicalState State = EChemicalState::Liquid;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Substance")
    FChemicalComposition Composition;

    /**
     * DT_Items row name this substance maps to when collected into the player
     * inventory. NAME_None means the substance is not collectible (e.g. Water
     * is a raw input, not a produced good). This is the single decoupling seam
     * between the chemical ID system and the legacy item system.
     */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Substance")
    FName InventoryItemRowName = NAME_None;
};

/** Data-table row: a refining recipe (required apparatus + inputs -> output). */
USTRUCT(BlueprintType)
struct FChemicalRecipe : public FTableRowBase
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
    FText RecipeName;

    /** Every apparatus in this list must be mounted for the recipe to run. */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
    TArray<EChemicalApparatus> RequiredApparatus;

    /** Every input substance (multiset) must be present for the recipe to run. */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
    TArray<EChemicalSubstance> RequiredInputs;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
    EChemicalSubstance OutputSubstance = EChemicalSubstance::None;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe", meta = (ClampMin = "0.1"))
    float ProcessTime = 5.0f;

    /**
     * true  = this recipe needs the stove power button ON to start (heat/cool reactions).
     * false = auto-starts once all required inputs are loaded (catalyst reactions).
     */
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Recipe")
    bool bRequiresHeat = false;
};
