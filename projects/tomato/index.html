一句话

火星上的一小块地，和一堆从垃圾里扒出来的零件。

这是个什么项目

《钛心番茄》是一款火星生存题材的 UE5 项目。玩家是一个叫 G-7 的垃圾回收站 AI， 守着一条把地球废弃物送上火星的传送带，要从这些东西里拆出零件、拼出设备、 炼出肥料，最终把一株番茄从种子养到结果。

核心循环是：

分析植株 → 筛选垃圾 → 拆件拼装 → 合成肥料 → 照顾植株 → 植株提出新需求

听起来简单，但它成立的前提是底层得同时搭起九个互相咬合的系统 —— 而它们之间的接口（什么算「可交互」、什么算「有电」、什么算「同一个装配体」） 才是这个项目真正的工程量所在。

世界观的三条硬设定

这三条不是氛围文案，它们直接改写了系统设计：

设定 对工程的约束
房间里本来什么都没有 花盆、基质、补光灯、滴灌、化学台、工具、连炉子都要玩家从垃圾拼出来 —— 所以拼装系统不是点缀，是主循环入口
火星没有四季，舱内没有昼夜温差 温度由焚化炉供热与舱外 −60℃ 散热动态平衡；光照靠玩家自制的 LED 生长灯。任何「春夏秋冬 / 昼温夜温 / 太阳能供暖」的模型都不成立
主角是湿件 G-7 的「脑子」是移植进来的捐献者神经组织，从 0.28 g 长到 1.7 g（人脑约 1400 g）。全程只有检测报告与数据，没人出现，也不表达情绪

第三条是叙事基调，但它反过来定了系统的表达方式：所有反馈都应该是读数， 而不是台词。植株缺氮就是把叶子变黄、把数值打在面板上，不弹「你的番茄饿了」。

九个系统

工程里按「系统功能边界」切成了九个模块，各有一份独立的开发约定与踩坑记录：

系统 管什么 关键资产 / 源码
农场 种子怎么长成植株、怎么被照顾与收获 AFarmableActorBase、UFarmingManagerComponent、DT_Farmables
交互 看向什么、能抓什么、按下去发生什么 AC_InteractionManager、BPI_Interactable、UInteractionBlueprintLibrary
拼装合成 散件怎么粘成装配体、装配体怎么固化成成品 BP_Glue、AC_AssemblySystem、DT_AssemblyRecipes
化学精炼 器材怎么摆、反应怎么跑、产物怎么收 UChemicalReactionComponent、DT_ChemicalSubstances
电力 谁在发电、谁在耗电、什么时候停电 UPowerAccountingComponent、DT_PowerConsumers
背包与快捷栏 物品怎么存、怎么上手、怎么丢回场景 AC_PlayerInventory、DT_Items、UHotbarManagerComponent

技术路线

  • 核心逻辑写 C++，编排与表现留蓝图。 状态机、数据结构、配方推导、 反射兜底这些「容易写错又难调」的部分下沉到 C++；材质、粒子、UI、连线留蓝图， 改起来不用等编译。工程里 74 个源文件基本都是按这条线落下来的。
  • 所有配方走 DataTable，但类型由 C++ 结构体兜底。 拼装配方、化学配方、 焚化燃料、耗电设备都是表；行结构是 C++ 的 USTRUCT， 表里填错类型编译期（或加载器）就会报，而不是等到运行时算出个垃圾值。
  • 组件化交互，接口只负责「能不能」。 交互不写在角色里，也不写在物品里 —— 物品实现接口，组件统一做射线、判定与分派；想被交互的东西不需要知道别的系统存在。
  • 判定放 C++，蓝图只做显示。 凡是「需要连一大片节点才判得出来」的逻辑 （交互阻断、热键栏分派、配方多重集匹配）都写成 BlueprintFunctionLibrary 静态函数， 蓝图侧只留一个 exec 引脚 —— 图变短了，也才查得动。
  • 桥接式开发。 编辑器内用 SoftUE 桥（soft-ue-cli + nwiro 两套 MCP）跑 Python 脚本建资产、查图表、验连接；改 C++ 走 Build.bat 全量编译（这版引擎的 Live Coding 在本机用不了）。

目前的状态

能跑通的：种植（种下 → 浇水 → 分阶段生长 → 收获）、电力记账与焚化产电、 物品拾取 / 丢弃 / 消耗、化学台蒸馏出水并收集、拼装的物理层与配方固化层、 倒液的水链路、组合体的存档与传送带刷出。

还没闭合的：六元素肥料成分到植株养分的数据通路、传送带导演（按需刷新的权重算法）、 物质回收闭环（回收率）、拆解链的右键入口、容器内容物的完整种类系统、 以及一批已经改完但只做过自动化状态量核验、还等着人实机确认手感的物理问题 （穿模、抖动、弹飞这类，脚本测不了）。

关于工作区

工程里的 U_Tomato 是这条主线的工作区 —— 上面九个系统都在这一个工作区里， 按模块拆成独立目录，编译单元和资产目录一一对应。工作区里另有三份副本的 「专职 Agent」定义（Claude Code / DSH / WorkBuddy 各一份）， 以及 .scratch/<功能>/issues/NN-*.md 形式的票据台账 —— 每个改动都有编号、 有根因、有验证方式，这也是这个项目能在几十轮迭代后还理得清的原因。

功能模块

农场系统

进行中

从一颗种子到一株结果的番茄 —— 分阶段生长、程序化株型生成、水肥照顾与收获拾取。

交互系统

进行中

看到什么、能抓什么、左键按下去到底发生什么 —— 以及为什么同一个滚轮在两种状态下语义完全不同。

拼装合成系统

进行中

散件怎么粘成装配体、装配体怎么固化成成品 —— 两层合成，加上一套物理约束的调参史。

化肥提炼与化学合成

进行中

把垃圾拆成零件、拼成器材、再炼成六种基础元素的完整链路 —— 以及为什么玩家该在乎自己捡的是什么。

电力系统

进行中

EU 记账 —— 谁在发电、谁在耗电、什么时候整舱停电，以及为什么「烧多少垃圾」是一个轻决策。

背包与快捷栏

进行中

一块物品结构体、一张物品总表、一套「上手/丢回场景」的往返契约 —— 以及一个没人填的数组造成的连环故障。

倒液与容器

进行中

液体在容器与器具之间的双向转移 —— 倒出去、也抽回来，以及一条没有任何报错的静默失效。

传送带

设计中

垃圾从哪来 —— 一条补位式刷新的带子、一套代位体机制，和一个还没做实的需求导演。

存档系统

进行中

植株、背包、快捷栏、装配体怎么活过重启 —— 以及一个「删掉的存档自己回来」的完整解剖。
