背包系统

一个组件装逻辑、一个组件装容器、一个组件只是空壳 —— 加物品是一个 While 循环配三张安全网，减物品要分"减一个"和"清空整叠"两条路，还有一支每帧跑的球形射线。

搁置蓝图ActorComponent网络复制

四个蓝图，四种角色

背包不是“一个蓝图干一件事”，是被拆成了四份，各自职责差别很大：

蓝图 父类 自建变量 干什么
InventorySystem ActorComponent 5 真正的逻辑：槽位数组、增删、追踪、掉落
BPC_ItemContainer ActorComponent 2 ⚠️ 从未被使用（见下）
BPC_PlayerInverntory BPC_ItemContainer_C 0 ⚠️ 上面那个的空壳子类，同样没用上
DD_InventorySlot DragDropOperation 2 拖拽时携带的数据载体，没有任何图

⚠️ 后两个类从来没被挂到任何东西上。 把全工程的 SCS 组件节点过一遍， 只会看到两种容器组件：BP_Testltem 上的 ItemDataComponent， 和 BP_Box 上的 InventorySystem_C。 也就是说：作者确实写了一套“通用物品容器”（BPC_ItemContainer， 用 S_ItemInfo 结构、有 FindEmptySlot / AddItem / UpdateUI）， 但箱子最后用的是普通 InventorySystem 组件，这套容器就一直躺在工程里。 这是本工程里最完整的一处 dead code。

InventorySystem 的五个变量

变量 类型 说明
Content F_SlotStruct 数组 全部槽位。这是背包的本体
InventorySize int 槽位总数，运行时可被 Array_Resize 改
InteractionRange double 交互射线的长度
LookAtActor Actor 当前“正在看”的 Actor，每帧被射线刷新
Onlnventoryupdate 多播委托 内容变化时广播出去，UI 靠它刷新

⚠️ Onlnventoryupdate —— 又是 l / I 的那类问题。本意 OnInventoryUpdate。 这个拼法一直传染到了 UI：BPC_ItemContainer 里显示的也是这个名字。 改名的连带成本已经不低了。

BPC_PlayerInverntory 是个空壳

它继承 BPC_ItemContainer，自建 0 个变量、0 条新逻辑， EventGraph 里只有四个节点：

ReceiveBeginPlay → CallParentFunction(BeginPlay)
ReceiveTick      → CallParentFunction(Tick)

就是“显式地把父类实现调一遍”。而这个类当前没有被挂到任何 Actor 上 —— 它既不覆盖行为、也不加状态。大概率是当时打算给玩家容器做特化， 建了类之后还没来得及用。而玩家和箱子实际用的都是 InventorySystem， 所以这两个容器类至今挂在工程里当装饰。

顺带：BPC_PlayerInverntory 里的 Inverntory 也拼错了。

InventorySystem 的图清单

组件里有 8 个真函数 + 10 段只挂桩的图：

图 节点数 类型
EventGraph 54 主逻辑 + 挂 IMC
RemoveFromlnventory 39 函数，最大的一坨
InteractionTrace 32 函数，每帧的交互射线
AddToInventory 26 函数
FindSlot 16 函数，找一个能塞的槽
GetDropLocation 12 函数，算掉落点
DEBUG_PrintContent 9 函数，调试打印
GetItemData 3 函数，查表
Onlnventoryupdate 1 空函数（真正的实现在委托上）
ReceiveTick / ReceiveBeginPlay 3 / 2 桩
Server_Interact / ServerCreateltemToWorld / ServerRemoveFromlnventory / Server_TransferSlots 各 3 桩
OnLocalInteract / MC_Update 3 / 2 桩
InpActEvt_IA_Interact / InpActEvt_One 各 3 输入桩

“桩”是什么意思：这些图的节点构成一模一样 —— FunctionEntry → CallFunction(ExecuteUbergraph_...) + 一个 SetVariableOnPersistentFrame。这是 UE 给函数入口 + 局部变量生成的骨架， 里面没有任何实际操作。

换句话说：Server_Interact、ServerCreateltemToWorld、MC_Update 这些名字听起来很重要（服务器端、多播），但函数体是空的。 它们是被“提前建好待填”的复制接口 —— 名字在、管道在、逻辑没写。 配合 SetReplicates（下面会提到），能看出联网是规划过但没落地的。

AddToInventory：一个循环配三张安全网

26 个节点的结构是这样的：

FunctionEntry
  → Local_HasFailed = false
  → Local_QuantityRemaining = 传入数量
  → WhileLoop (Local_QuantityRemaining > 0 且 not Local_HasFailed)
       ├→ FindSlot(ItemID)          找已有同类且未满的槽
       ├→ Any Empty Slots Available  找不到就找空槽
       ├→ IfThenElse ─┬─ Add to Stack     堆进现有槽
       │              └─ Create New Stack  开一个新槽
       └→ DecrementInt(Local_QuantityRemaining)
  → FunctionResult

三张安全网指的是：

  1. Local_HasFailed 作为循环退出条件 —— 一旦某一步失败，BooleanAND 直接让 WhileLoop 停下， 不会变成一个死循环。
  2. FindSlot 先于“找空槽” —— 优先堆叠，堆不下才开新槽。
  3. Not_PreBool / Greater_IntInt 两个前置检查 —— 数量为 0 或已经失败时直接跳过循环体。

WhileLoop 是这份工程里唯一一个循环加物品的实现 —— 传 200 个苹果进来， 它会一次一个地跑 200 轮。对原型来说够用，但一次加几十个就会卡一帧。

RemoveFromlnventory：全工程最长的函数

39 个节点，而且它是唯一一个带内部分区的函数：

内部分区 干什么
物品数量减1 槽里的 Quantity - 1
清空物品槽 把整个槽 SetFieldsInStruct 成空

主线：

FunctionEntry
  → Content[Index] → BreakStruct → LocalItemID / LocalQuantity
  → MC_Update                                  ← 先广播一次（多播 RPC）
  → IfThenElse: (RemoveWholeStack == LocalQuantity) OR IsConsumed
       ├─ 真 → 清空物品槽（Array_Set 写回空结构）
       └─ 假 → 物品数量减1（Array_Set 写回减一后的结构）
  → IfThenElse → ServerCreateltemToWorld ×2    ← 掉落到世界里
  → PrintString（两处调试打印）

两个值得记的设计点：

  • RemoveWholeStack == LocalQuantity 用 OR 拼了 IsConsumed —— 意思是“要么玩家选择丢掉整叠，要么这叠本来就被消耗光了”， 两条路都走“清空槽”。用 OR 而不是两个分支，是省节点的写法。
  • MC_Update 在减数量之前调 —— 先把“要变了”广播出去， 再改数据。UI 因此会刷新两次（一次预告、一次实际）， 这在纯本地是无害的，但如果在联网下就是一个多余的 RPC。

InteractionTrace：每帧一支球形射线

32 个节点，是“看向什么”的唯一来源。构造射线的方式：

GetOwner → K2_GetActorLocation ─┐
GetActorForwardVector × InteractionRange ─┘→ Add_VectorVector → 终点
GetPlayerCameraManager ─→ MakeArray(忽略自己) → SphereTraceSingle
                                                     ↓
                                              BreakHitResult → IfThenElse

用 SphereTraceSingle 而不是 LineTraceSingle —— 球体有半径， 所以准星不用精确落在物品上也能命中，手感宽容得多。

命中之后是一段配对式的高亮管理：

新命中组件 ≠ LookAtActor 上的组件
   → 对旧的 LookAtActor 发 UnLook 消息
   → LookAtActor = 新命中
   → 对新 LookAtActor 发 LookAt 消息
  • 用 GetComponentByClass 从 Actor 上取组件，再发接口消息 —— 说明真正做高亮的是组件（见交互与高亮）， 不是 Actor。
  • UnLook 被调了两次（编号 3056 与 1744 两个 Message 节点）—— 两个分支各一次，说明“目标变了”和“什么都没命中”分别处理。
  • NotEqual_ObjectObject 后面接赋值，保证只在新旧不同的时候才切换—— 避免每帧都重发 LookAt。

MakeArray 里装的是要忽略的 Actor（自己）， 所以射线不会打到自己身上。

GetDropLocation：掉落点带随机

12 个节点，把“丢出去”这件事做得像样：

GetOwner → K2_GetActorLocation ─┐
GetActorForwardVector ──────────┤
RandomUnitVectorInConeInDegrees ─┘→ ×距离 → +位置 → −一个向下的偏移
                                              → LineTraceSingle → BreakHitResult
  • RandomUnitVectorInConeInDegrees —— 在角色前方的一个锥形范围内取随机方向， 所以丢出来的东西不会每次落在同一点，也不会丢到背后去。
  • 最后接一发 LineTraceSingle —— 把落点贴到地面上。 这一步很重要：不做的话，在斜坡上丢物品会掉进地形里。
  • ⚠️ 距离、锥角、向下偏移这三个数都是引脚常量 —— 都看不到。

FindSlot 与调试函数

FindSlot（16 节点）：遍历 Content，对每个槽做两个判断 —— 槽.ItemID == 传入 ItemID（EqualEqual_NameName）并且 槽.Quantity < Get Max STack Size（Less_IntInt）。两个都成立就返回这个槽的索引。 注意 ItemID 的类型是 Name。

GetItemData（3 节点）：一个 GetDataTableRow 就完了 —— 从 Item_Data 表里按行名取一行。这是全工程唯一一处读配置表的入口， 所有物品属性都从它出来（见物品数据）。

DEBUG_PrintContent（9 节点）：ForEachLoop + BreakStruct + 一串 Conv_*ToString + Concat_StrStr + PrintString， 把整个背包内容打成一行字符串。它在 EventGraph 里被一个按键事件调用 （InputKey 节点 + InpActEvt_One 桩），也就是按 1 键就把背包内容打到屏幕上 —— 一根遗留的调试开关。

EventGraph 里的两件事

54 个节点，其中一块分区叫「挂载IMC_Inventory」：

ReceiveBeginPlay → GetOwner → DynamicCast → IsLocallyViewed → IsValid
                 → GetController → GetSubsystemFromPC → AddMappingContext

输入是背包组件自己挂的 —— 挂的还正是角色那张 IMC_Inventory_catAWSD（这个越界行为在增强输入里记过）。

另一件是 SetReplicates：

EventGraph → GetOwner → SetReplicates(true)

作者调过复制开关，配合前面那批空的 Server_* / MC_* 函数 —— 联网的骨架搭了一半。但 InventorySystem 是 ActorComponent， 组件复制和 Actor 复制不是一回事，SetReplicates 加在组件上 还要靠 SetIsReplicatedByDefault，这里没看到。所以这条线是断的。

目前的进展

  • Content 槽位数组 + InventorySize 运行时可变
  • AddToInventory：优先堆叠、其次开新槽、带失败保护
  • RemoveFromlnventory：区分“减一个”与“清空整叠”，带内部分区
  • FindSlot 按 ItemID + 未满双条件查槽
  • InteractionTrace：球形射线 + LookAt / UnLook 配对
  • GetDropLocation：锥形随机方向 + 打地贴合
  • Onlnventoryupdate 委托驱动 UI 刷新
  • GetItemData 统一从 Item_Data 表读属性
  • ⚠️ BPC_ItemContainer / BPC_PlayerInverntory 两个容器类零引用 —— 箱子实际用的是 InventorySystem
  • ⚠️ BPC_PlayerInverntory 是空壳，只有 CallParentFunction，无任何作用
  • ⚠️ Server_* / MC_Update / OnLocalInteract 全是空函数 —— 联网只搭了架子
  • ⚠️ SetReplicates 加在 ActorComponent 上，缺 SetIsReplicatedByDefault，复制不会生效
  • ⚠️ AddToInventory 用 WhileLoop 一次一个，批量入包会卡帧
  • ⚠️ Onlnventoryupdate / BPC_PlayerInverntory 拼写错误已扩散到 UI
  • 没有堆叠上限的提示（FindSlot 里查了上限，但界面上没告诉玩家为什么堆不进去）
  • 没有重量 / 容量上限，InventorySize 是唯一约束
