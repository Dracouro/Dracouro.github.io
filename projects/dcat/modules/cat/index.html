猫角色

一个 EventGraph 里九块分区、83 个节点，把走跑蹲跳和超级跳全连了出来 —— 顺带发现模板角色自己就被人改过，而且蹲下的碰撞体比站着还高。

搁置蓝图增强输入CharacterMovement

它继承自谁

BP_CATTTTTT 的父类不是 Character，而是模板的第三人称角色 BP_ThirdPersonCharacter：

项 值
父类 /Game/ThirdPerson/Blueprints/BP_ThirdPersonCharacter.BP_ThirdPersonCharacter_C
骨骼网格 CAT3_0，相对位移 (-22, 3, -85.8)
依赖 BP_ThirdPersonCharacter、StandardMacros、PC_MyPlayerController
被依赖 ABP_CAT（动画蓝图盯着它）
组件 Capsule、CharacterMesh0、CameraBoom、FollowCamera、Arrow、ChildActorComponent（变量名 BP_Weapon）

有一条线索能直接看出「是在模板上原地改的、不是照着新建的」： 工程配置里的 ProjectName 至今还是 Third Person BP Game Template。

自己加的五个变量

变量 类型 说明
CD_SuperJump double 超级跳的冷却/计时，配合 Delay 复位
CurrentWeapon Actor 当前武器实例。不是 ChildActorComponent，是真的武器 Actor
IsWeaponInHand bool 武器在手上还是背上，动画蓝图要读它
SourceInventory InventorySystem_C 背包组件引用，标了 ExposeOnSpawn（生成时就传进来）
TurnRateGamepad_0 double ⚠️ 零引用的残留 —— 全工程没有任何节点读它，是继承变量重名时自动加的 _0 副本

变量类别顺序被整理成了 无 / 摄像机 / 输入 / 事件图表 / 默认， 说明细节面板的排列是动过手的，不是随手堆的。

三级数值：引擎 → 模板 → 这只猫

「这只猫跑起来什么感觉」不在节点里，在类默认值上。 而且这里有个必须分层看的事实 —— 模板角色本身就已经被改过了， 所以不能拿引擎默认值当参照物：

属性 引擎默认 模板角色 这只猫 谁改的
MaxWalkSpeed 600 500 160 模板改了一档，猫又砍到 27%
JumpZVelocity 420 700 900 两级连续拔高，最终 2.1×
GravityScale 1.0 1.75 2.5 两级连续拔高
MaxWalkSpeedCrouched 300 300 80 只有猫改了
CrouchedHalfHeight 40 40 100 只有猫改了 —— ⚠️ 见下
AirControl 0.05 0.35 0.35 模板改的，猫没动
MaxAcceleration 2048 1500 1500 模板改的，猫没动
BrakingDecelerationWalking 2048 2000 2000 模板改的，猫没动
GroundFriction 8.0 8.0 8.0 三级都没动
胶囊半径 34.0 35.0 35.0 模板改的
胶囊半高 88.0 90.0 90.0 模板改的

读法：

  • 猫自己动手的只有五个数：MaxWalkSpeed 160、JumpZVelocity 900、 GravityScale 2.5、MaxWalkSpeedCrouched 80、CrouchedHalfHeight 100。
  • 其中前四个是同一个方向：平时慢慢走（160），一跳起飞（900）， 落得快（重力 2.5），蹲下更慢（80）。配合模板留下的 AirControl 0.35 （空中能改 35% 的方向）—— 合起来是蹦床跑酷的手感，不是第三人称射击的手感。
  • 另外三个常被误认为是「作者调的手感」的数（AirControl / MaxAcceleration / BrakingDecelerationWalking）其实都是模板角色改的，猫一层没碰。 只看最终值很容易把功劳记错对象 —— 这也正是分三层量它的价值。

⚠️ CrouchedHalfHeight = 100：站立的胶囊半高是 90， 蹲下却是 100 —— 蹲下时碰撞体反而比站着更高。 按 CharacterMovementComponent 的语义，蹲下会把半高换成 CrouchedHalfHeight，所以这个值会让猫蹲下时被顶高、 或者在低矮处卡住。大概率是填错的数（想填 40 或 60 那类）， 但这里只按实测记下来 —— 是否真的表现异常，要在实机里蹲一下才敢下结论。

EventGraph：83 个节点，9 块分区

整张图没有一行注释文字，只有九块彩色分区（EdGraphNode_Comment）—— 这是这份工程唯一的结构说明，而且分区名是中文的：

分区 节点数 干什么
挂载增强输入 7 ReceivePossessed 时把 IMC 塞进输入子系统
JUMP AND RUN 9 起跳前先量速度，分两支
SuperJump 11 抬高 JumpZVelocity → 跳 → 延时复位
crouch 4 按一下切一次蹲
获取角色偏移 11 WASD 按相机朝向换算成移动
旋转视角 5 鼠标转 Yaw，抬头低头转 Pitch
走路/奔跑 6 切一次 MaxWalkSpeed
切换武器装备的位置 14 手 ↔ 背 两套对称分支
获取武器对象实例并将武器附加到角色手上 7 BeginPlay 时抓出武器挂到手上

九块分区恰好覆盖全部 83 个节点，没有孤儿节点 —— 说明图是按分区整理过的，不是边写边堆。

⚠️ 一个必须说清的限制：蓝图节点之间的连线在纯文本层面拿不到。 UE 5.7 里 EdGraphPin 不是 UObject（obj list class=EdGraphPin 返回 0 个对象）， 插件接口也刻意不返回连线（源码注释原话是「Agent 不应当用它做连线依据」）。 所以下面的读法是由节点类型 + 节点名 + 坐标顺序 + 分区归属推出来的： 参与者和顺序基本可信，但分支之间的配对是推断，不是断言。

逐块拆解

挂载增强输入（7 节点）

ReceivePossessed → IsValid(宏) → DynamicCast → GetSubsystemFromPC → AddMappingContext
  1. 挂输入用的是 ReceivePossessed，不是 BeginPlay。 IMC 属于「控制器」，而 Pawn 的 Possessed 才是控制器到位的时刻； 用 BeginPlay 在某些重生 / 换人流程里会拿到空控制器。
  2. GetSubsystemFromPC 拿的是 EnhancedInputSubsystemInterface， 再调 AddMappingContext —— 这是 5.x 的标准姿势，不是老式 EnableInput。
  3. 前面套了 IsValid 宏 + DynamicCast —— 作者在防 「控制器可能不是 PC_MyPlayerController」这一手。

JUMP AND RUN（9 节点）

IA_Jump_cc → GetVelocity → VSize → GreaterEqual_DoubleDouble → IfThenElse
                                                             ├─ FlipFlop → MaxWalkSpeed 赋值
                                                             └─ CharacterMovement.Jump

分区名字就是设计意图：起跳不是无脑跳，先量当前速率 （VSize(GetVelocity)），跟阈值比大小，跑着跳和站着跳走两条不同的路。

合理读法：这是「助跑跳」—— 到一定速度以上起跳时顺手把 MaxWalkSpeed 拨到另一档，保留冲量。但哪一支落到哪个结果，从文本推不出来。

SuperJump（11 节点）

整张图里逻辑最完整的一段，也是「超级跳」名字的由来：

自定义事件 SuperJump_Reset ─┐
DoOnce(宏) ─────────────────┤
CharacterMovement.JumpZVelocity 赋值（×2）
Delay ──────────────────────┤
CD_SuperJump（读） ──────────┘
CallFunction SuperJump_Reset
CharacterMovement.Jump
StopJumping
  • JumpZVelocity 被写了两次 —— 一次抬高、一次还原。 也就是说超级跳不是一个新动作，是把初速临时换一档： 900 换成更高的值，过一会儿再换回来。
  • DoOnce 防连按（CD_SuperJump 是那个冷却计时）。
  • Delay 延时复位 —— 不还原的话玩家会一直保持超级跳初速。
  • StopJumping 是短跳（松手就收），配合 Delay 才有可控高度。
  • 复位被提成了独立函数 SuperJump_Reset，在两处被调（事件入口一次、延时到点一次）。 这是九块分区里唯一一处函数级复用 —— 其余全是复制粘贴。

crouch（4 节点）

IA_Crouch → FlipFlop(宏) ├─ Crouch
                         └─ UnCrouch

按一下切一次，不是按住。IMC 里 LeftControl → IA_Crouch 的触发器是 Pressed， 与这里的 FlipFlop 正是「点按切换」的标准组合。

获取角色偏移（11 节点）

IA_MoveForward_cc ─┐
IA_MoveRight_cc   ─┴→ GetControlRotation → MakeRotator → ├ GetForwardVector → AddMovementInput
                                                         └ GetRightVector   → AddMovementInput
  • 移动方向跟的是 GetControlRotation（相机朝向），不是角色朝向。 第三人称必须这么做 —— 跟角色朝向的话，转身时会「边走边画圈」。
  • 中间 MakeRotator 的作用是抹掉 Pitch/Roll、只留 Yaw， 否则视线朝下时人会往地里钻。
  • 前后和左右各自接一个 AddMovementInput，是两条独立输入链， 不是先合成 Vector2D 再走一次。

旋转视角（5 节点）

AI_Turn_cc   → AddControllerYawInput
IA_LookUp_cc → NegateFloat(宏) → AddControllerPitchInput
  • ⚠️ AI_Turn_cc 少打了一个 I —— 应该是 IA_Turn_cc。 资产名错了，引用它的地方也跟着错，改名要连 IMC 一起改。
  • Yaw 直通，Pitch 过一次 NegateFloat —— 非反转的鼠标纵向， 取反是「鼠标上推 = 抬头」的默认约定。

走路/奔跑（6 节点）

IA_Sprint → FlipFlop(宏) → CharacterMovement(读 ×2)
                          ├ MaxWalkSpeed 赋值
                          └ MaxWalkSpeed 赋值

冲刺也是切换式，在 MaxWalkSpeed 两档之间来回拨。 两个赋值节点各写一个不同的常量 —— 但常量值看不到 （引脚默认值既不在 obj dump 的输出里，也不在插件返回的引脚信息里）。

这是纯蓝图工程的代价之一：数值藏在引脚上。 想知道奔跑档到底是 400 还是 600，只有在编辑器里点开那个节点。

切换武器装备的位置（14 节点）

两块严格对称的分支 —— 一眼看出是复制一份再改：

IA_ToggleWeapon → FlipFlop ┤
   ├─ CurrentWeapon + Mesh → K2_AttachToComponent → IsWeaponInHand → PlayAnimMontage
   └─ CurrentWeapon + Mesh → K2_AttachToComponent → IsWeaponInHand → PlayAnimMontage
  • 两条支路都读 CurrentWeapon（挂谁）与 Mesh（挂到哪）， 调 K2_AttachToComponent，翻转 IsWeaponInHand，最后播一个蒙太奇。
  • 武器不是生成/销毁，是重新挂 —— 同一个武器 Actor 在两个挂点之间搬家。 所以既没有生成开销，也不会出现「切枪时旧枪残留」。
  • PlayAnimMontage 让手部动作跟上（掏枪 / 收枪）—— 这正是 ABP_CAT 要读 IsWeaponInHand 的原因（见动画蓝图）。
  • ⚠️ IsWeaponInHand 的两个赋值节点分居两支，理论上一个写 true 一个写 false； 但和 MaxWalkSpeed 一样，布尔常量也看不到。

获取武器对象实例并将武器附加到角色手上（7 节点）

ReceiveBeginPlay → BP_Weapon(组件读) → ChildActor → CurrentWeapon 赋值
                          → Mesh → K2_AttachToComponent → IsWeaponInHand = true
  • 这里的 BP_Weapon 是那个 ChildActorComponent 的变量名 （UE 按子 Actor 的类自动命名），所以 BP_Weapon → ChildActor 就是 「取出这个组件里挂着的子 Actor」。
  • 也就是说：武器 Actor 是随角色一起被 spawn 出来的（作为子 Actor 组件的一部分）， BeginPlay 时把它从组件里「摘出来」存进 CurrentWeapon 并挂到网格上。
  • 这块与上一块是一对：BeginPlay 负责第一次上手，IA_ToggleWeapon 负责之后来回切。
