动画蓝图

一个蓝图、三条图、47+23+13 个节点 —— 把"蹲没蹲、在不在空中、手里有没有枪"算成四个布尔，再喂给一张带分层混合的状态机。而骨架的 129 根骨骼全叫 Bone_000 这样的名字。

搁置蓝图动画蓝图状态机ControlRig

一副骨架，129 根没名字的骨头

先说要紧的：CAT3_0_Skeleton 里 129 根骨骼全部叫 Bone_000 到 Bone_128， 外加一堆 Bone_00N_end / _end_end 的末梢辅助骨。

这些名字是 FBX 导入时自动生成的 —— 说明这份模型导入时没有做骨骼名映射， 源文件里的骨骼名（或者压根没有好名字）被直接丢弃了。

这件事是整个动画模块的起因，它解释了三件看起来不相关的事：

  1. 为什么武器的挂点插槽要叫 weapom_attach_hand_r —— 骨骼没有名字可依，只能靠人工标注。
  2. 为什么分层混合里只能写 Bone_102 这种编号（见下）—— 想写 spine_03 也没得写。
  3. 为什么工程里有两个 Control Rig：CR_Catt（作者自己做的）与 SK_CAT3_0_CtrlRig（给网格自动生成的那份）—— 在一副无名骨架上做动画，必须先把骨骼人工分组标注一遍。

十个变量：九个布尔与浮点，一个引用

ABP_CAT（父类 AnimInstance）自建 10 个变量，全部是中间计算结果， 没有一个来自外部输入：

变量 类型 谁写它
Character Character（对象引用） BlueprintInitializeAnimation
MovementComponent CharacterMovementComponent 同上
IsCrouching bool Character.bIsCrouched
IsInAir bool MovementComponent.IsFalling
GroundSpeed double VSize(Velocity)
IsMoved bool GroundSpeed >= 阈值
Movementlnput bool VSize(GetLastMovementInputVector) > 阈值
IsWeaponInHand bool Character 上的同名变量（见武器）
LeanAmount double CalcLean 函数，FInterpTo 平滑
PreviousRotation Rotator CalcLean 函数，存上一帧朝向

⚠️ Movementlnput —— I 是大写的，本意是 MovementInput。 这是本工程第四处同类问题（另见 Interactlnterface、RemoveFromlnventory、 AI_Turn_cc），根源是这台机器上小写 l 与大写 I 字形太像。

一个值得注意的设计：IsWeaponInHand 不是动画蓝图自己算的， 它是从角色身上读过来的。角色的切武器逻辑 负责翻这个布尔，动画蓝图只负责消费。职责分得很干净 —— 动画不反过来决定游戏状态，这是对的。

三条图

ABP_CAT 里有三处图，规模差别很大：

图 节点数 干什么
EventGraph 47 每帧把游戏状态翻译成动画参数
AnimGraph 23 姿势的流向：状态机 → 缓存 → 分层 → 输出
CalcLean（函数） 13 算转身时的身体倾斜量

另外还有 4 个自动生成的 EvaluateGraphExposedInputs_..._TransitionResult 小图 —— 这是状态机的转换条件被写成蓝图表达式时，UE 自动开的口子。 4 个这个数字说明：状态机里有 4 条转换是蓝图条件驱动的，其余是默认的 “自动规则”（比如“剩余时间 > 0”）。

EventGraph 的九块分区

和猫角色一样，这张图没写任何注释文字， 靠九块彩色分区组织。但这里有三块分区名是英文的：

分区 节点数 语言 干什么
Set references to owning character when this blueprint initializes. 5 英 BlueprintInitializeAnimation 里抓角色与移动组件
Only update values if the character is valid (character exists in the world and the reference is set). 3 英 整张图的守卫 IsValid
是否合法 2 中 上面那块的后半截（IsValid 宏）
获取角色是否在蹲伏状态 4 中 读 bIsCrouched
速度Speed,是否在空中 6 中 Velocity → VSize、IsFalling
获取武器是否在角色手中 4 中 从角色读 IsWeaponInHand
角色是否正在移动中 4 中 GroundSpeed >= 阈值
获取角色偏移值 4 中 调 CalcLean
获取是否正在移动 5 中 GetLastMovementInputVector → VSize → >

三块英文分区是照抄了 UE 第三人称模板自带动画蓝图里的注释—— 模板的 ABP_Manny 里就是这两句（“Set references to owning character when this blueprint initializes.” / “Only update values if the character is valid…”）。也就是说这份动画蓝图是从模板改出来的， 前两块连注释一起留着了，后面新加的部分才用中文起名。 这种“半英文半中文”的分区命名，本身就记录了改造的顺序。

初始化与守卫

BlueprintInitializeAnimation → GetOwningActor → DynamicCast(Character) → Character 赋值
                             └→ DynamicCast → MovementComponent 赋值
BlueprintUpdateAnimation → IsValid(Character) → 后面所有计算
  • 用 BlueprintInitializeAnimation 而不是每帧 TryGetPawnOwner —— 抓一次就够，省掉每帧的类型转换。
  • 每帧的开头套一个 IsValid 守卫。这是必须的：动画蓝图的更新 可能早于 / 晚于 BeginPlay，不防的话第一帧就会空引用崩溃。
  • 同样的守卫在「获取是否正在移动」那块用了 TryGetPawnOwner 而不是 缓存的 Character —— 两种取法在同一个图里并存，属于改动留下的不一致。

「是否在移动」用了两个不同的判据

这是整个模块最有意思的一处设计：

变量 判据 来源
IsMoved VSize(Velocity) >= 阈值 实际速度
Movementlnput VSize(GetLastMovementInputVector()) > 阈值 输入意图

一个量“真的动了没”，一个量“玩家想动没”。 两套都有意义：前者用于蒙太奇/受击打断类判断，后者用于 “顶着墙推时不要停走步动画”这类手感修正。 作者没有把两者合并成一个 —— 说明他意识到这两件事不是一回事。

两个阈值常量都看不到（引脚常量不出来），所以无法判断谁更严格。

AnimGraph：姿势是怎么流过去的

23 个节点，结构可以按分区读成四段：

分区 内容
缓存Locomotion姿势 StateMachine（移动状态机）→ SaveCachedPose #1
缓存MainStates姿势 StateMachine（主状态机）→ SaveCachedPose #2
缓存左手姿势 Slot(DefaultSlot) → SaveCachedPose #3
缓存全身姿势 Slot(FullBody) → SaveCachedPose #4

然后是最后一段汇流：

缓存Locomotion姿势 ─┐
缓存MainStates姿势 ─┤→ LayeredBoneBlend → BlendListByBool → Root
缓存左手姿势     ─┘        ↑
缓存全身姿势 —— UseCachedPose ×5（供上面几个节点取用）

三个组件节点各自查到的配置：

节点 关键配置 含义
Slot #1 SlotName = DefaultSlot 蒙太奇的默认槽（PlayAnimMontage 走这里）
Slot #2 SlotName = FullBody 第二条槽，供全身类蒙太奇覆盖
LayeredBoneBlend BlendMode = BranchFilter，LayerSetup = ((BranchFilters=((BoneName="Bone_102", BlendDepth=1))))，BlendWeights = (1.0) 从 Bone_102 这号骨起，往下整枝覆盖
BlendListByBool BlendTime = (0.1, 0.1)，BlendType = Linear 两个姿势之间 0.1 秒线性过渡

Bone_102 + BlendDepth=1 是这里的核心：它把骨架从第 102 号骨 （大概率是脊椎/胸腔那一节）开始往下的部分整枝替换， 也就是经典的”下半身跑动 + 上半身做别的“。 BlendWeights = 1.0 表示这一层是全权重覆盖，不是叠加。

这也回过头印证了上面那句：因为骨骼没名字，作者只能靠编号找位置。 Bone_102 是“第 103 根骨”—— 这个数字只有对着骨架树数一遍才知道是哪。 换个人接手，改这里几乎等于重新数一遍骨头。

BlendListByBool 的驱动来自 IsInAir 取反（Not_PreBool）， BlendTime 两个通道都是 0.1s —— 用于在空中姿势与地面姿势之间切换。

状态机里有 4 条蓝图转换

前面提到有 4 个 EvaluateGraphExposedInputs_..._TransitionResult 图。 它们说明状态机的 4 条转换节点上，条件不是“自动规则”，而是勾了蓝图表达式。

⚠️ 状态机的内容读不到：AnimStateNode / AnimStateTransitionNode 在这一版引擎里不是 UObject（obj list outer=<EditorStateMachineGraph> 返回 0 Objects，obj dump 报 No objects found）， 和 EdGraphPin 的情况一样。所以状态的名字、状态的个数、 哪条转换挂在哪两个状态之间 —— 这些全部拿不到。 能确认的只有：2 个状态机、4 条蓝图驱动转换。

CalcLean：唯一一处真正的“手感算法”

13 个节点，是全工程为数不多能看出来是公式而不是连线的逻辑：

GetOwningActor → K2_GetActorRotation ─┐
PreviousRotation ─────────────────────┤→ NormalizedDeltaRotator（本帧转了Δ角）
                                      │
GetWorldDeltaSeconds ─────────────────┤→ FInterpTo（按帧时长平滑）
LeanAmount（上一帧的值）───────────────┘
                                          → LeanAmount 赋值
                                          → PreviousRotation = 本帧朝向
  • NormalizedDeltaRotator 算出朝向变化量，取的是标准化差值 （跨 ±180° 不会跳变）—— 这是正确写法，说明作者知道这个函数的用途。
  • FInterpTo 用帧间隔做插值，所以转身越快、倾斜量涨得越快； 停下后 LeanAmount 会平滑回落到 0。这就是第三人称里“转弯时人往内侧压”的效果。
  • ⚠️ FInterpTo 的 InterpSpeed 是引脚常量 —— 看不到， 所以倾斜的“软硬”程度无从判断。

资产群

B_Cat/ 下的动画资产一共 40 个文件，分成三组：

组 数量 命名 说明
动画序列 30 Anim_* 在 Animations/
动画蒙太奇 2 HosterWeapon、FallBody_Weapon 切武器用的，见武器
混合空间 6 BS* 在 BlendSpace/，1D 与 2D 混用
动画蓝图 1 ABP_CAT 本页主角
Control Rig 2 CR_Catt、SK_CAT3_0_CtrlRig 手动做的 + 自动生成的

混合空间这六个名字记一下：BS1D_Jump、BS_Cat888、BS_Crouch、 BS_JumpFall_cc、BS_RUN、BS_WalkRunLean。

序列的命名是按动作代号缩写的：J1–J4 / JJ / JJJJJ / JS / JUP / JF02 是跳跃家族，WTL / WTR / RTL / RTR（含 B 后缀）看着像左转/右转， JUP 是 Jump Up，Anim_stop 是刹停。 这套缩写对外人几乎不可读 —— 加上 129 根无名骨骼， 这份动画资产的可维护性是很低的，属于“作者自己还记得、别人接不了手”的状态。
