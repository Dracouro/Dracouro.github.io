武器与持握

一把武器，两个挂点，一个插槽名 —— 而那个插槽名拼错了。武器从来不是"生成"出来的，是从子 Actor 里摘出来再挂到手上的。

搁置蓝图ChildActorComponent骨骼插槽

武器本体是个空壳

BP_Weapon 是整个工程里逻辑最少的一个蓝图：父类是最朴素的 Actor， 零个自建变量，EventGraph 里只有三个空事件。

项 值
父类 /Script/Engine.Actor
自建变量 0 个
组件 DefaultSceneRoot + SkeletalMesh（两个 SCS 节点）
EventGraph 3 个空事件（BeginPlay / ActorBeginOverlap / Tick）+ UserConstructionScript
依赖 无（CachedDependencies 与 CachedDependents 都是空） 
BP_Weapon (Actor)
└─ DefaultSceneRoot            (SceneComponent)
   └─ SkeletalMesh             (SkeletalMeshComponent)
        └─ SkeletalMeshAsset = /Game/B_Cat/Meshes/WP01

三个事件都是空的（只有事件节点，没有连线、没有调用）。 也就是说 BP_Weapon 自己不干任何事 —— 它的全部行为都写在角色那边。 这是个刻意的拆法：武器是“一个带网格的道具”，持握逻辑归角色。

一处配置上的小别扭：SkeletalMesh 组件的 AnimationMode 是 AnimationBlueprint，但 AnimationBlueprint = None。 结果是武器网格不会播放任何动画，纯粹刚性地跟随手部插槽 —— 对一个静态武器来说结果没错，但这个组合是“模式设错了、恰好没出问题”。

它是怎么被塞进角色里的

角色侧用的是三层嵌套，这是理解整套持握的关键：

层 对象 类型 相对缩放
角色蓝图 BP_CATTTTTT Character —
挂点组件 BP_Weapon（变量名） ChildActorComponent，挂在原生 CharacterMesh0 上 1.0
子 Actor 模版 ChildActorTemplate BP_Weapon_C 实例 —
武器网格 SkeletalMesh SkeletalMeshComponent 0.007

ChildActorComponent 的 ChildActorClass 指向 BP_Weapon_C —— 这个组件本身就带一个“模板子 Actor”，角色一被生成，这个子 Actor 就跟着被 spawn。

⚠️ 关于那个 0.007：WP01 这个网格资产的原始尺寸是很大的 （包围盒 Z 半长 5346，即原始高度约 10693 单位）， 靠组件上的 RelativeScale3D = 0.007 缩回正常尺度。 猫的骨骼网格也一样：CAT3_0 原始高度约 10954 单位， 组件缩放 0.025。两个 bAbsoluteScale 都是 False，所以缩放会层层相乘。 这段只记实测数字 —— 具体在实机里武器大小合不合适，要摆出来看才知道。

挂点：一个拼错的插槽名

挂点信息不在蓝图节点的连线上，而在 SCS 节点的两个字段里：

AttachToName              = weapom_attach_hand_r
ParentComponentOrVariableName = CharacterMesh0
bIsParentComponentNative  = True

翻译过来：挂在原生网格组件 CharacterMesh0 的 weapom_attach_hand_r 这个骨骼插槽上。

⚠️ weapom —— 少了一个 n。规范的写法是 weapon_attach_hand_r。 这个词是作者自己在网格编辑器里新建插槽时敲的，敲错之后再没改回来。 它只出现在这一个地方，所以只影响可读性，不影响运行 —— 但只要挂点要迁移到另一个网格上，就得连这个错字一起复制过去。

旁边还有个细节：bIsParentComponentNative = True —— 说明挂点选的是 引擎自带的 CharacterMesh0，不是蓝图里新建的组件。所以这个挂点在 BP_CATTTTTT 里是看不见的（它在父类 BP_ThirdPersonCharacter 上）， 只能从 SCS 节点的字段读出来。

角色侧的两段逻辑

第一段：BeginPlay 把武器“摘”出来

分区「获取武器对象实例并将武器附加到角色手上」（7 节点）：

ReceiveBeginPlay
  → BP_Weapon（读组件）→ ChildActor（读属性）→ CurrentWeapon 赋值
  → Mesh → K2_AttachToComponent → IsWeaponInHand = true
  • BP_Weapon 是 ChildActorComponent 的变量名，ChildActor 是它的属性 —— 这一对读出来就是“这个组件里挂着的那个子 Actor”。
  • 拿到之后存进 CurrentWeapon，再用 K2_AttachToComponent 把它重新挂一次。
  • 为什么要重挂？因为 ChildActorComponent 已经把子 Actor 挂在 weapom_attach_hand_r 上了，这里再挂一次是把武器的 Actor 本体 改为直接依附 Mesh —— 让后续切手/切背时有一个统一的操纵对象。

一句话概括这一步：武器不是“生成”的，是“拿出来”的。 角色一生成，武器就已经作为子 Actor 存在了；BeginPlay 只是把它提升成一个 有名字的引用（CurrentWeapon），好让后面的切换逻辑能找到它。

第二段：Q 键在两套挂点之间搬家

分区「切换武器装备的位置」（14 节点）—— 两块严格对称的分支：

IA_ToggleWeapon → FlipFlop ┤
   ├─ CurrentWeapon + Mesh → K2_AttachToComponent → IsWeaponInHand 赋值 → PlayAnimMontage
   └─ CurrentWeapon + Mesh → K2_AttachToComponent → IsWeaponInHand 赋值 → PlayAnimMontage
  • 两支都读 CurrentWeapon（挂谁）和 Mesh（挂到哪），调同一个 K2_AttachToComponent，翻转 IsWeaponInHand，最后各播一个蒙太奇。
  • ⚠️ 两个 K2_AttachToComponent 的插槽参数看不到。节点的引脚签名是 self / Parent / SocketName / LocationRule / RotationRule / ScaleRule / bWeldSimulatedBodies， SocketName 在，但它的值不在任何可读输出里（见下面那句关于引脚常量的说明）—— 一个是手、一个是背，从节点名推得出来，具体插槽名要到编辑器里点开。
  • ⚠️ 同理，IsWeaponInHand 的两个赋值一个是 true、一个是 false，常量值看不到。
  • PlayAnimMontage 用的是同一个节点的 AnimMontage 引脚 —— 图里没有任何读变量的节点喂给它，说明蒙太奇是直接以引脚常量写死在节点上的， 所以“哪一支播哪一个”同样读不出来。工程里一共只有两个蒙太奇（见下）， 从命名看几乎必然就是这两个，但哪个对应哪一支是推断。

为什么引脚常量就是读不到：这一层被查实了 —— UE 插件返回的引脚 JSON（UAL_BuildPinsJson）只输出 name / dir / category / sub_category / is_array / is_reference / is_const / sub_category_object / friendly_name，没有 DefaultValue 字段。 而开关式蓝图里最关键的“手感数值”（速度档、插槽名、触发方向） 恰恰全是引脚常量。这不是这一次没抓到，而是这条通路本身就不带。

两把武器网格，只有一个在用

/Game/B_Cat/Meshes/ 里有五个资产，其中三个属于武器：

资产 用了吗
WP01 ✅ 武器网格，BP_Weapon 的 SkeletalMeshAsset
WP01_Skeleton ✅ 它的骨架
WP01_PhysicsAsset ✅ 它的物理资产
wp ✅ 材质（唯一一个材质槽，槽名就叫 wp）
ot_we001_BML ❌ 孤儿 —— 导入了但全工程零引用

WP01 的规模：1310 三角面 / 915 顶点，一个材质槽，ForwardAxis = Y。

WP01_Skeleton 里残留着 ot_we001 和 Armature 两个字符串 —— 说明 WP01 与那个没用的 ot_we001_BML 是同一批导入的， 其中一个后来被弃用了。这类“导进来一批、只用其中一个”的残留， 是快速原型阶段的典型痕迹。

那两个动画蒙太奇

角色在切武器时播的蒙太奇，在 B_Cat/Animations/ 下 —— 夹在一堆 Anim_* 序列中间，只有这两个是蒙太奇：

资产 类型 用到的插槽 引用的序列
HosterWeapon AnimMontage DefaultSlot + FullBody Anim_hand_idle、Anim_idle
FallBody_Weapon AnimMontage DefaultSlot + FullBody Anim_hand_idle、Anim_idle

HosterWeapon 明显是 Holster Weapon（收枪入套）的手滑写法 —— 和 weapom_attach_hand_r 是同一类问题。FallBody_Weapon 看名字是“手持武器的下落姿势”。

两个蒙太奇都同时写进 DefaultSlot 与 FullBody 两条槽轨道， 正好对应动画蓝图里那两个 Slot 节点。

命名问题小结

这个模块里“名字不对但能跑”的地方密度偏高，一并列出来：

资产 / 字段 现名 应该是
骨骼插槽 weapom_attach_hand_r weapon_attach_hand_r
蒙太奇 HosterWeapon HolsterWeapon
材质 wp 有意义的材质名
网格 ot_we001_BML 弃用未删
变量 CurrentWeapon（类型是 Actor） 类型能收窄到 BP_Weapon_C

目前的进展

  • 武器独立成 BP_Weapon（Actor + 一个骨骼网格），零逻辑
  • 用 ChildActorComponent 预先挂载，BeginPlay 取出为 CurrentWeapon
  • K2_AttachToComponent 通过骨骼插槽挂到手上
  • Q 键切换手 / 背，两支对称，各带一个蒙太奇
  • 两个真正的动画蒙太奇（HosterWeapon / FallBody_Weapon）
  • ⚠️ 插槽名拼错：weapom_attach_hand_r
  • ⚠️ 蒙太奇名拼错：HosterWeapon
  • ⚠️ ot_we001_BML 孤儿资产未清理
  • ⚠️ 两个 K2_AttachToComponent 的插槽参数、两个 IsWeaponInHand 常量值无文档
  • 武器没有任何数值（伤害 / 耐久 / 弹药）—— 表里有这些列，但武器没接
