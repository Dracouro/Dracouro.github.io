暖洋洋呆猫村

一只跑酷的猫，和一套从零手搓的背包。九天做完、停摆两年，全部用蓝图 —— 工程里一行 C++ 都没有。

概览

功能模块

猫角色增强输入武器与持握动画蓝图背包系统交互与高亮物品数据界面关卡与遗留

一句话

一只猫在一片积木场里跑跳，捡东西、开箱子、翻背包 —— 所有系统都用蓝图连出来，没有一行 C++。

这是个什么项目

《暖洋洋呆猫村》是一个 纯蓝图 的 UE5 第三人称原型：一只猫（网格 CAT3_0）在 一片用 SM_Cube / SM_QuarterCylinder / SM_Ramp 搭出来的跑酷场里跑跳， 路上能捡东西进背包、能开箱子、能切武器。

它的看点不在玩法，在实现方式：这是一个把「角色控制 + 增强输入 + 背包数据 + 交互高亮 + 一整套 UMG」全部用蓝图连出来的工程 —— 装不下 C++ 的一行代码。

工程里没有 Source/ 目录，没有 .cpp，没有 .h。 九个模块的所有逻辑，都是 K2Node。

它同时也是一份很典型的中途工程样本：2024 年 11 月做了九天就停了， 两年后才重新打开，于是工程里同时留着「当年的做法」和「当年没做完的地方」—— 一半的迁移、拼错的资产名、空掉的控件、零引用的基类。 这些东西没有掩饰地留在了工程里，也是这份记录里最有信息量的部分。

玩法形状

一条很短的循环，但每一环都是自己搭的：

跑跳（含超级跳） → 看向物品（描边高亮） → 按 E 拾取 → 背包里整理 / 拖拽 / 丢弃 → 切武器

环节 做什么 落在哪个模块
跑跳 WASD + 手柄，走 / 跑 / 蹲 / 跳 / 超级跳（带冷却） 猫角色
切武器 Q 在「手持」与「背上」之间切换，带动画蒙太奇 武器与持握
找东西 每帧从相机向前的球形射线，命中后物体上描边 交互与高亮
捡起 按 E，物品写进背包槽，场景里那份自己销毁 背包系统
整理 背包 / 箱子两张网格，可拖拽互换、可右键弹菜单 界面

技术路线

  • 纯蓝图，零 C++。 没有 Source/，没有编译步骤 —— 改完直接跑。 代价也直接摆在工程里：凡是「需要连一大片节点才判得出来」的逻辑 （背包增删、槽位查找、堆叠）都变成了几十个节点的大图， 最长的 RemoveFromlnventory 有 39 个节点，AddToInventory 26 个。
  • 增强输入（Enhanced Input）从第一天就用上了。 不是老式 Axis/Action Mapping， 而是一个 InputMappingContext + 10 个 InputAction， 取反、死区、HoldAndRelease 这些都在资产里配，不写代码。
  • 数据驱动，但只驱动了一半。 物品定义在 Item_Data 表里、行结构是蓝图结构体 F_ItemStruct；但槽位用的是另一个结构体 F_SlotStruct， 而且两个结构体的 ID 类型不一样（见物品数据）。
  • 组件化交互。 交互能力不写在角色里：物体实现 Interactlnterface 并提供 HighLightComponent，角色侧的 InventorySystem 只负责射线与分派。
  • 善用引擎自带的重定向链。 猫的骨架配了 IKRetargeter + IKRigDefinition + ControlRigBlueprint，说明动画是从外部（Mixamo 一类）重定向进来的， 而不是自己 K 的。

目前的状态

能跑通的：角色移动与跳跃（含超级跳冷却）、增强输入全链路、 蹲伏 / 冲刺 / 视角旋转、武器切手持与背上（带蒙太奇）、 看向物体描边高亮、按 E 拾取进背包、物品从背包丢回世界、 背包 / 箱子两张网格的拖拽互换、右键动作菜单（使用 / 丢弃1个 / 丢弃全部）、 以及按 I 打开的角色菜单。

还没闭合的：

  • 物品数据的迁移只做了一半。 新结构体 S_ItemInfo 和它的表 ItemInfo_Data 都建好了，但表里一行数据都没有，工程里也没有任何地方在用它 —— 老的 F_ItemStruct + Item_Data（两行）仍是唯一在跑的通路。
  • 堆叠逻辑写了，数据说不该堆。 AddToInventory 里有完整的 「找同类槽 → 塞满 → 开新堆」，但表里两个物品的 IsStackable? 都是 false。
  • W_Inventory（背包主界面）仍是空壳。 布局搭到了三层嵌套， 但最里层的 Border_40、HorizontalBox_281 都没有子控件； 唯一有文字的 TextBlock_215 写着占位符 PlayerName。
  • W_Hotbar（快捷栏）完全没有逻辑，只有三个空事件； W_ItemInfo 里的标题与数量还是 文本块 / 99 这种默认值。
  • 一整套多人网络函数（Server_* / MC_Update / SetReplicates）挂着，但没人调用。 拾取走的是本地直连，不是服务器往返。

工程里的疑点与残留（不阻塞，但都是坑）：

现象 说明
ProjectName 还是 Third Person BP Game Template 工程从头到尾没有改过名
配置里的默认 GameMode 还是模板的 BP_ThirdPersonGameMode 真正生效的是关卡 WorldSettings 里覆盖的 GM_Catt。改配置不会有效果
AI_Turn_cc 应该是 IA_Turn_cc，少打一个 I
RemoveFromlnventory / Onlnventoryupdate / ServerRemoveFromlnventory 用的大写 I 而不是小写 l —— ln 与 In 混用
BPC_PlayerInverntory 拼错的 Inverntory，而且它是个空组件，只转调父类
W_InventorySLOT 与 W_InventorySlot 两个几乎同名的资产共存，前者控件树是空的
BP_ItemMaster 一个零引用的物品基类，没有任何逻辑
Saved/Crashes/ 留了一批崩溃转储

关于工作区

工程正源在 D:/UE/UUUUUUUUUUUUUUUUUUU/U_DCat002/（注意目录多一个 0， 但 .uproject 与日志都叫 U_DCat02）。原始引擎关联是 5.4； 为了读取蓝图结构，另建了一份 5.7 副本在 .../暖洋洋呆猫村 5.7/。

工程里没有 Source/、没有 .git、没有 README、没有设计文档 —— 九天的开发没留下任何文字说明。这份记录是从蓝图本身反推出来的：见关卡与遗留。

⚠️ 关于读法：本工程是纯蓝图，蓝图对象在 UE 里不是文本资产， 所以本站的「源码」区块在它下面没有内容 —— 那是正常的，不是漏了。 蓝图的可读形式只有「节点列表」和「图」，前者已按模块整理进各页正文， 后者需要从编辑器里手工复制（见关卡与遗留）。

功能模块

猫角色

搁置

一个 EventGraph 里九块分区、83 个节点，把走跑蹲跳和超级跳全连了出来 —— 顺带发现模板角色自己就被人改过，而且蹲下的碰撞体比站着还高。

增强输入

搁置

一张 IMC、十个 IA、十六行按键映射。工程从第一天就用 Enhanced Input —— 连蹲和冲刺的触发器都被手调过。

武器与持握

搁置

一把武器，两个挂点，一个插槽名 —— 而那个插槽名拼错了。武器从来不是"生成"出来的，是从子 Actor 里摘出来再挂到手上的。

动画蓝图

搁置

一个蓝图、三条图、47+23+13 个节点 —— 把"蹲没蹲、在不在空中、手里有没有枪"算成四个布尔，再喂给一张带分层混合的状态机。而骨架的 129 根骨骼全叫 Bone_000 这样的名字。

背包系统

搁置

一个组件装逻辑、一个组件装容器、一个组件只是空壳 —— 加物品是一个 While 循环配三张安全网，减物品要分"减一个"和"清空整叠"两条路，还有一支每帧跑的球形射线。

交互与高亮

搁置

一个接口、三个函数、四处实现，而四处实现彼此都不一样 —— 真正干活的是挂在物品上的两个组件，物品 Actor 自己反倒是个空壳。至于描边，查到最后发现只写了"关"、没写"开"。

物品数据

搁置

三个枚举、三个结构体、两张表 —— 以及一次做到一半的迁移：新结构体丢掉了旧结构体的两个字段、补上了两个新字段，而那张新表里一行数据都没有。

界面

搁置

11 个 UMG，控件的骨架搭得很完整 —— 但热键栏和信息面板的图是空的，还有两个控件连控件树都没有。真正在干活的是 5 个。

关卡与遗留

搁置

一个 38 个 Actor 的跑酷测试场、一块还写着 "Third Person Template" 的牌子、一套把 GameMode 改在关卡里而不是配置里的分层，以及一份长到需要单独开一页的遗留清单。
