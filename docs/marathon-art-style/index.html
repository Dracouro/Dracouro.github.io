这份文档只回答一个问题：《Marathon》(2025) 那种「图形写实主义」的美术风格，拆开来看究竟是什么，在 UE5 里怎么用同样的路子做出来？

全部结论来自对本机真实安装包的实测 —— .pkg 解析、2,313 个网格与 14,654 张贴图的逐条统计、66 万条场景实例的还原。不是经验之谈，也不是对官方分享的复述：文中的每一个预算数字都能追到一个实测分位数，出处见 §10。

游戏目录全程只读：只做包解析，不写盘、不注入进程。

0. 一句话结论

风格的关键不在 shader，在「模块化套件 + trim sheet + 大色块 + 后处理定调」。

原包数据本身就证明了这点：工程量约 80% 在规范与资产组织，只有 20% 在材质。 如果你把主要精力花在写复杂 shader 上，方向就已经错了。

反过来说也一样成立：在 UE5 里堆法线细节、堆高频噪声、堆金属反射，会立刻把画面拉向「写实向」，和最省力也最有效的做法背道而驰。

三条口径约定（不说清楚，数字之间就会互相矛盾）：

  1. 「全库 14,654 张」和「9,757 条引用」是两个统计面。 前者是磁盘上导出的全部贴图；后者是被 2,313 个网格引用到的那部分，同一张贴图被多个网格共用会重复计数。本文凡说「sRGB 3,644 张」「BC5 19 条」之类，都是引用侧口径。
  2. 面数与分位数都按「单件资产」聚合，不是按顶点、也不是按场景实例展开后的总量 —— 实例是复用，不该重复计入资产规模。
  3. 几何一律取「还原后的真值」：顶点按最长轴归一化再加回局部包围盒偏移，对齐残差中位 0.00005；尺寸口径为 1 游戏单位 ≈ 1 m。

2. 风格拆解：从实测数据反推「图形写实」

2.1 七条观察 → 七条结论

观察（实测） 数据 对风格的含义
UV 挤在窄带 密度 p90/p10 中位 9.6；典型 u ∈ [0.500, 0.521] 大量 trim sheet / 平铺：造型靠方正大块面，细节由贴图条带承担
单件面数低 三角 p50 526、平均 1,705 模块化套件，形状由大平面 + 倒角构成
实例量巨大 单图 24.3 万 实例 / 全库 66.3 万 空间节奏靠重复构件，不靠单体雕刻
主色是绝对主体 sRGB 3,644 张（BC7_SRGB 1,521 + BC1_UNORM 2,123） 信息主要在 albedo，不在法线高频
单通道灰度成规模 BC4 1,195 张 粗糙度 / AO 走大区块，避免噪声
HDR 极少 BC6H 仅 43 张 自发光 / 玻璃是点缀，不是主体
场景件没有切线流 stride 16（位置 + 单位四元数），无 tangent 环境件基本不吃法线贴图 → 形状优先、法线次要

这七条合起来，就是「图形写实」的技术定义： 大形状 + 平铺色块 + 低频粗糙度 + 克制的高光。

第 7 条值得单独看一眼，因为它最容易被忽略：场景网格的顶点流只有 16 字节 —— 位置（4×i16）之后跟的是单位四元数（4 分量模长实测 100% = 1.0000，把局部 +X 轴旋到法线，同向率中位 97.7%），根本没有切线。没有切线就没有可靠的切线空间，也就意味着环境件的法线贴图这条路在原包里是关掉的。

下面这张图就是上面七条的空间形态 —— 一整张地图的等距预览（还原后的几何，不含贴图）：

图 1 · 单张地图的几何还原。注意画面重心是几块大面积平板（大块面），而它们之间的“信息密度”全部来自同一批小构件的高频重复 —— 这正是「模块化套件 + 实例重复」的视觉结果，也是 §2.3 要讲的复用策略。

2.2 它不是传统 PBR

把「传统 PBR（metal-rough）流程」的每一条特征拿去对，几乎全是负结论：

传统 PBR 特征 实测 判定
法线贴图是标配（BC5，两通道） BC5 全库仅 16 张 / 引用仅 19 条 ✗
每顶点有切线（TBN 矩阵） 场景件 stride 16，没有切线流 ✗
网格自带贴图绑定 24,325 个网格里 0 个直接引用贴图 ✗
材质资产含贴图槽 材质链只到 DXBC 着色器，texture_ref 恒为空 ✗
有成百上千张烘焙 lightmap HDR（BC6H）仅 43 张 ✗

实际形态是：几何静态挂着色器 + 贴图在运行期绑定 + 大色块 / 低频粗糙度。

  • 几何：静态直连 —— 实例记录里直接带网格 tag，SStaticMesh +0x08 直指网格数据。是直接用。
  • 着色器：静态直连 —— 每个网格静态挂 4 个 DXBC 着色器（中位），全库引用 1,645 个去重着色器。是直接用，但它是 D3D 字节码，不能移植 —— 只能当“它在做什么”的参考，材质必须重写。
  • 贴图：运行期绑定 —— 数据层没有网格↔贴图绑定（0 / 24325）。贴图是运行期靠参数挂上去的。

这也解释了为什么这个风格看起来“更简单”：简单不是省事的结果，是复用策略的结果。

2.3 原理：复用的三个乘数

视觉变化 = 几何复用(实例变换) × 贴图复用(UV 子区) × 外观复用(每实例参数)
成本只按「1 份」计
  • 为什么省：真正的瓶颈是 draw call 与带宽。实测 1,645 个着色器 + 24,301 个网格 + 9,757 条贴图引用，撑起了 66.3 万条实例 —— 这就是复用的量级。
  • 风格是效率约束的审美化。三条复用手段各自对应一个形状后果：
复用手段 形状后果
形状通用（模块化套件） → 方正大块面
UV 分格（trim sheet） → 细节低频、成条带
靠参数差异（MI / 实例数据） → 色块与磨损，而非结构差异
  • 代价：绑定被推迟到运行期，UV 是 trim 域。所以「数据层读不到贴图、读不到 per-draw 缩放」不是数据缺失，是这套原理的必然结果 —— 在逆向时它是障碍，在制作时它是设计选择。
  • Nanite 时代只解决了几何那一层（自动量化 + 免 LOD）；贴图与外观的复用仍然需要 trim sheet + Master Material + Material Instance 来支撑。

4. 模块化规范

尺度、栅格、pivot、命名这四样必须在建第一个构件之前定死；它们是「构件能互换、能吸附、能共享贴图」的前提。

项 规定 依据
尺度 1 游戏单位 ≈ 1 m；UE5 里 ×100（1 m = 100 uu） 单图跨度实测 1,229 单位（t4_marsh）≈ 1.2 km 量级
栅格 基准 200 uu；墙高 400 / 600；层高 600；走廊净宽 400 / 600 单件尺寸量级 ≈ 2 单位 = 200 uu
Pivot 统一底部中心（墙 / 柱 / 箱）；地砖 / 天花板用角点 保证全部可吸附、可平铺
吸附 编辑器 Grid Snap = 50；模块化件吸附到 200 —
命名 SM_<区域>_<类型>_<尺寸>_<变体>，如 SM_Deck_Wall_400_A 原包没有资产名（tag 是哈希），必须自己定
碰撞 模块化件一律 Simple Collision（盒），禁止复杂碰撞 几十万实例，复杂碰撞必崩
接缝 构件边必须落在 grid 上；转角用专门的 90° 件，不要靠缩放拼 缩放会破坏 UV 密度与吸附

下图是这个规范的视觉目标 —— 方正大块面 + 倒角，几乎找不到“雕刻感”的曲面：

图 2 · 前哨站类场景的几何还原。左侧的方正构件是主体，中间那团密集的细碎形状是大量小装饰件的堆积 —— 二者用的是同一套栅格与同一张 trim sheet，“复杂”完全是复用堆出来的，不是靠单体精度。

5. 材质与贴图流程（复刻的核心）

5.1 Master Material —— 一个就够

Texture Object Parameter × 4    T_Base(albedo) / T_Trim / T_Mask / T_Normal
Scalar · Vector Parameter       TrimScale, TintColor, RoughMin/RoughMax
Custom Primitive Data × 4       Tint 偏移 · UV 偏移/缩放 · 磨损强度 · 区域 ID
  • Mask 通道约定（对齐原包的单通道灰度习惯）：R = Roughness、G = AO、B = Metallic
  • 不给环境件接 Normal 输入 —— 原包场景件没有切线流（见 §2.1 第 7 条）
  • 需要每实例差异（颜色 / 磨损 / UV 偏移）时走 Custom Primitive Data，不要为每个变体做一份新材质

5.2 Trim Sheet 工作流

这是复刻里最核心的一件事，四步：

  1. 做 1 张 2048² trim sheet，切 8~16 条材质带（金属 / 混凝土 / 警示条 / 格栅 / 线缆…）
  2. 每个构件的 UV 只映射到其中几条带内 → 全场景共享 1 张贴图
  3. 大面积表面（地板 / 长墙）用平铺（UV 超出 0–1，Wrap 采样）
  4. 结果：显存与 draw call 都压到极低，而且天然产生“色块化”的图形感

原包实测就是这个模式的铁证：多个网格的 UV 恰好从 u = 0.500 起始、区间只有 0.02 宽 —— 这就是一条 trim 带。

图 3 · 一个模块化构件的四联证据图。上左几何（方正 + 倒角）；上右贴上主色后的样子 —— 注意是大色块而非结构细节；下左 UV 压图：整套 UV 只占了贴图一个很小的角落，大面积区域完全空着，这正是“UV 是 trim 域、不是 0–1 展开”的直接证据；下右主色贴图本身。

图 4 · 同一原理用在角色 / 装备上：UV 是被排布到贴图条带里的（绿色线框 = 三角面投影），而不是自由展开。这也是为什么“把原包 UV 当 0–1 展开来用”一定不对。

图 1~4 都是从游戏资产还原出来的几何渲染，只作技术分析示意，不构成任何可复用资产。

5.3 用 MI 替代“运行期贴图绑定”

原包的做法是「网格上静态挂 4 个 DXBC 着色器 + 贴图在运行期给」（实测：24,325 个网格里 0 个直接引用贴图）。在 UE5 里的正确对应不是去搞 per-draw 常量缓冲，而是：

1 个 Master Material + N 个 Material Instance（每个 MI 只换 Texture 参数）

一个 shader 家族覆盖全场景，MI 之间的差异只产生常量差异 —— 这正是原包那种“共享着色器”的做法，而且完全绕开了不可移植的 DXBC。

6. UE5 侧关键开关（逐条对应实测）

复刻目标（原包实测） UE5 里怎么设
顶点 i16 量化 + 四元数法线 Nanite（自动量化 + 顶点去重），不要手搓
UV 是 u16 Static Mesh Build Settings：Use Full Precision UVs 保持关闭
单段索引 / 无 LOD 链 场景件走 Nanite（免 LOD）；非 Nanite 件必须生成 Auto LOD
每网格静态挂 4 个 shader 1 Master Material + 大量 MI
贴图运行期绑定 Material Instance 的 Texture 参数
per-draw UV 缩放 / 偏移 Per-Instance Custom Data / Custom Primitive Data
66 万实例 HISM / PCG；大世界加 World Partition + HLOD
环境件无切线 环境材质不接 Normal，用 Cavity / AO 撑形状
BC4 单通道灰度 Compression = Masks (no sRGB)，或打包 ORM
BC6H HDR Compression = HDR
海量 1024² 贴图 上 Streaming Virtual Texture (SVT)，别全常驻

⚠️ Nanite 对 WPO / 遮罩 / 半透明的支持随版本变化，逐项在目标版本上确认；本文讨论的静态构件不受影响。

7. 场景搭建

三档分工，各管一类东西：

手段 铺什么 规模
HISM 固定重复构件（墙 / 地 / 柱 / 箱） 几十万实例
PCG（5.2+） 随机 / 衰减类（碎石、设备、线缆、杂物）；spline 模式做管线与走廊排布 长条构件尤其对口（原包大量存在）
手工 只放 hero 与关卡节拍点 —
  • World Partition：按 200 m 分格（1.2 km 地图 ≈ 6×6 格）
  • 光照：直接用 Lumen。

    依据：原包 HDR 贴图只有 43 张 —— 不太可能是大规模烘焙 lightmap（那会产出成百上千张），更像动态 GI + 稀疏的 HDR 数据。所以没有“必须烘焙”的理由。

8. 后处理定调（“图形感”从这来）

Post Process Volume 上逐项定：

项 建议 理由
Color Grading 挂 LUT（DaVinci / PS 里做，导出 3D LUT） 一次定死全片色调
Bloom 收窄 + 降强度 图形感的关键：高光不要糊开
Film Grain 关 颗粒会立刻把画面拉向写实
Chromatic Aberration ≤ 0.2 微量即可
Vignette 轻 —
Tone Curve 拉一点对比 配合大色块
  • 需要描边 / 边缘光时，用 Post Process Material（Blendable） 做深度 + 法线边缘检测。不要在每个材质里塞 Fresnel —— 那会破坏批处理，也会让风格变“脏”。
  • 材质端：Roughness 走 trim sheet 区块化，避免高频纹理噪声。

9. 五阶段流程与验收标准

阶段 产出 验收（达到才算过）
1. 定规格 本文档落成团队约定 + UE5 导入预设（Interchange）+ 命名 / grid 新导入的资产自动带对压缩设置与 16-bit UV，不用手改
2. 先做材质 1 个 Master Material + 1 张 2048² trim sheet + 1 张通用法线 用 3 个 MI 就能铺满一整面墙，且 draw call 不随构件数增长
3. 建套件 30~60 个模块化构件（墙 / 地 / 顶 / 柱 / 管 / 箱） 全部 Nanite、共享 trim、pivot 可吸附、单件 ≤ 2000 三角
4. 铺场景 HISM / PCG 铺满 + World Partition 目标规模下 60 fps；实例数 ≥ 10⁵ 仍不卡
5. 定调压测 LUT + 后处理 + GPU Profiler top-5 后处理开销 ≤ 2 ms；shader 复杂度图无红区

顺序不能换：先材质后建模。 trim sheet 的条带决定了构件该怎么切 UV；反过来做的话，套件建完还要回去重展 UV —— 这正是 §2.3 那个“复用”结构对流程顺序的硬约束。

模块化套件（modular kit） 一套按统一栅格与 pivot 制作、可互相拼装的构件集合
HISM Hierarchical Instanced Static Mesh，UE5 的层级实例化静态网格，铺重复构件的首选
PCG Procedural Content Generation，UE5.2+ 的程序化放置框架
CPD Custom Primitive Data，UE5 里给每实例传自定义参数的机制
DXBC D3D DirectX Bytecode，D3D 的着色器字节码；不可移植到 UE5
per-draw 常量 每次绘制调用传的一组常量（原包 (34,1)）；原包中该条目为空，运行期才填
BC4 / BC5 / BC6H / BC7 块压缩纹理格式：单通道灰度 / 两通道法线 / HDR / 通用高质
